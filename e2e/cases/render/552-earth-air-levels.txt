# An atmosphere can now author altitude/temperature LEVELS instead of one scale
# height (#552 A4). The loader integrates the column hydrostatically from the authored
# sea_level_pressure and each level's temperature (atmo.h:resolveAtmoLevels, #739), so the
# density the dossier prints is what that pair implies rather than a typed number, and the
# air rows stop being
# IMPLIED by H and start being the profile the body states. Earth wears the 1976
# standard atmosphere because it is the only body with published numbers to copy.
#
# tests/test_drag.cpp pins the law and tests/test_scenarios.cpp pins the shipped file's
# numbers (288.1 K / 101.3 kPa / 340.5 m/s at Earth's datum). This pins the last inch,
# which no unit test can see: WHICH LABEL the dossier picks. "(isothermal)" is a warning
# that a body has no lapse rate, so it must not sit beside a body that authored one, and
# it must still sit beside the ones that did not. When this case was written that was
# Venus, Mars, Titan and most of the file; the corpus pass that gave Mars and the rest a
# stated air column has narrowed it to Titan, so the warning is pinned there now.
#
# Earth's "atmosphere top" row is pinned too: a layer table has no H for top() to
# multiply by 10, so it must author `height`, and 85 km is what its old H 8500 already
# derived. Author it any other way and the rotating-frame shell and the science
# Flying/LowOrbit bands move with it (#625).
#
# The "to 71.8 km" is the topmost level's base in GEOMETRIC metres, which is what a system
# file speaks (#690). The 1976 standard states that row at a GEOPOTENTIAL height of 71 km,
# and the generator converts every row -- altitude and lapse rate, since a lapse is K per
# that same height coordinate -- against Earth's radius on the way out, so the row that used
# to print 71.0 now prints 71.8: 11 km is 11,019 m, 51 km is 51,411.6 m. A file that kept
# the standard's numbers would still resolve and still print a plausible dossier, and this is
# the ONE atlas row the mistake moves: air density, sea-level T, pressure and "atmosphere
# top" all come from fields the conversion leaves alone. tests/test_scenarios.cpp is the
# guard; this row is where the same mistake is visible to a human.
NAME earth-air-levels
CLAIM A body that authors a layer table reports that profile in its dossier instead of a temperature implied by a scale height.
KIND invariant
ARGS --system res/systems/solar_system.json --timeout 6 --atlas-dump 4000
FORBID error:
CHECK re.search(r"\[atlas\] Earth weight=.*?atmosphere top\s+85\.0 km", out, re.S)
CHECK re.search(r"\[atlas\] Earth weight=.*?air profile\s+7 levels to 71\.8 km", out, re.S)
CHECK re.search(r"\[atlas\] Earth weight=.*?air density\s+1\.225 kg/m3", out, re.S)
CHECK re.search(r"\[atlas\] Earth weight=.*?air temp \(sea level\)\s+288\.1 K \(15\.0 C\)", out, re.S)
CHECK re.search(r"\[atlas\] Earth weight=.*?air pressure\s+101\.3 kPa", out, re.S)
# 340.5 rather than the 340.3 this case pinned until #630: Earth's gamma is no longer a
# typed 1.4 but what its authored dry-air mix resolves to (1.4015, because a CO2 molecule
# lifts the heat capacity), and sound speed goes as sqrt(gamma). Same for the Mars row
# below: its molar mass is now a CO2-heavy mix's 0.0435, not a typed 0.044.
CHECK re.search(r"\[atlas\] Earth weight=.*?sound speed\s+340\.5 m/s", out, re.S)
# The two negatives have to bound the WHOLE Earth block. Every fact row is its own
# "[atlas]   " line, so the obvious out.split("[atlas] Earth weight=")[1].split("[atlas]
# ")[0] is only the rest of the HEADER line -- measured, it covers "routine approach_dv=0
# discovered=0%" and nothing else, so these two would pass no matter what the dossier
# printed. (?=\[atlas\] \w+ weight=|\Z) stops at the next body (Earth's Moon follows it
# here) and still matches if Earth were last in the dump.
CHECK "scale height" not in re.search(r"\[atlas\] Earth weight=.*?(?=\[atlas\] \w+ weight=|\Z)", out, re.S).group(0)
CHECK "isothermal" not in re.search(r"\[atlas\] Earth weight=.*?(?=\[atlas\] \w+ weight=|\Z)", out, re.S).group(0)
# And the label still rides with the bodies that DO owe the warning -- though the corpus has
# moved since this case was written, and the warning's carrier moved with it. Mars used to be
# the example (rho0 0.016, H 11000, CO2-heavy mix); it now wears a two-level table of its own
# (214.0 K at the datum, lapse -4 K/km to 16.5 km, then isothermal at 148.0 K), so its row
# reads "(sea level)" like Earth's and its block carries no warning word at all.
CHECK re.search(r"\[atlas\] Mars weight=.*?air profile\s+2 levels to 16\.5 km", out, re.S)
CHECK re.search(r"\[atlas\] Mars weight=.*?air temp \(sea level\)\s+214\.0 K \(-59\.1 C\)", out, re.S)
CHECK "isothermal" not in re.search(r"\[atlas\] Mars weight=.*?(?=\[atlas\] \w+ weight=|\Z)", out, re.S).group(0)
# Titan is the one body left in this file whose air is still one scale height, so it carries the
# warning now: scale height 20.0 km, density 5.300 kg/m3, g 1.35 m/s2 -- rho x g x H = 143.1 kPa
# beside the row's 143.6 kPa, and the temperature that density-and-pressure pair implies through
# the authored N2/CH4/H2 mix is the 90.5 K the row prints. "(isothermal)" is the dossier saying
# "I did not author a lapse rate, so this temperature is BACK-OUT, not a reading" -- and 90.5 K
# is Titan's own mean to within a few K, which is why the pair is plausible rather than a clue.
CHECK re.search(r"air temp \(isothermal\)\s+90\.5 K", re.search(r"\[atlas\] Titan weight=.*?(?=\[atlas\] \w+ weight=|\Z)", out, re.S).group(0))
CHECK re.search(r"\[atlas\] Titan weight=.*?scale height\s+20\.0 km", out, re.S)
