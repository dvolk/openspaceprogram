NAME 745-asked-for-a-temperature-a-world-without-one-says-why
CLAIM Ask the Surface Map for a temperature this world cannot support and it dashes the temperature columns and names the reason -- a flat grey field and a sentence, not a colour nobody priced.
KIND invariant
# Moho is the tempting mistake: it is a hot airless rock with a stated surface temperature, so
# a default of "bare rock" or "no swing means no swing" would paint something plausible here.
# It has an ANCHOR and no authored swing -- Mercury's corpus pair was REFUSED (#742), and Moho
# borrows Mercury, so the refusal propagates. The other three refusals (a banded giant with no
# ground, #738; a world with no anchor at all; a satellite whose analogue refused) are pinned by
# unit tests in tests/test_surfmap.cpp, which is where a policy table belongs; this case pays
# for the one game run that proves the game prints the sentence at all.
ARGS --timeout 10 --time-accel 1 --system res/systems/ksp_system.json
ARGS --surfmap-log --surfmap-n 64 --surfmap-body Moho --surfmap-map temperature
ARGS --sim-press 3000,0,M
CHECK len(surfmap) >= 1
CHECK last(surfmap)["body"] == "Moho"
CHECK last(surfmap)["map"] == "temperature" and last(surfmap)["level"] == "ground"
# The picture exists (64x32 pixels were painted) but carries no temperatures: the columns dash
# and the note says which absence this is (#726 keeps these states apart, #727 renders them).
CHECK last(surfmap)["w"] == 64 and last(surfmap)["h"] == 32
CHECK last(surfmap)["temp"] is None
CHECK "no authored swing" in last(surfmap)["note"]
CHECK last(surfmap)["albedo"] is None and last(surfmap)["shaded"] is None

FORBID temp=0.00
FORBID anchor=0.00
