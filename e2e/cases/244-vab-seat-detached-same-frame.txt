# The VAB prunes the seat plan once per frame (vabUpdate), so a launch arriving
# in the SAME frame as a detach used to reach the fill loop holding an entry that
# names a part no longer in the build:
#   osp: src/vab.cpp: Assertion 'pi < v->parts.size() && suit != nullptr' failed
# The plan is built the way a player builds it -- aim at capsule_r1.5h3_2, right-
# click, pick the seat, pick Ace -- and only the SAME-FRAME pair is hooked: two
# hooks can fire detach and launch inside one frame, while a player's clicks land
# frames apart. The assert is in the launch path itself, so vabLaunch prunes its
# own plan before reading it (issue #288). The plan is dropped out loud, so the
# crew falls back to the pad's line rather than half-filling from a stale choice.
#
# This is the one case that keeps --vab-launch, and it was checked rather than
# assumed: switching it to --ui-click "VAB TopBar/LAUNCH" (like every other case
# now does) left it PASSING with vabLaunch's own prune removed. A click presses
# in one frame and releases in the next, so vabUpdate prunes the plan in between
# and the stale entry never reaches the fill loop. Same-frame arrival needs two
# hooks.
NAME vab-seat-detached-same-frame
ARGS --vab e2e/fixtures/two_capsules.json --kerbals e2e/fixtures/three_kerbals.json
ARGS --time-accel 1 --timeout 8 --frame-cap 30
ARGS --ui-focus 2000,capsule_r1.5h3_2
ARGS --sim-mouse 2100,0,CUR,CUR,RMB
ARGS --ui-click 2600,"Capsule (3m)##capsule_r1.5h3_2/Seat 1##s0"
ARGS --ui-click 3000,"##Combo_00/Ace"
ARGS --vab-detach 1 --vab-detach-at 5000 --vab-launch 5000
EXPECT [vab] dropped the seat plan for 'capsule_r1.5h3_2' 'Ace' (it left the build)
EXPECT [toast] No seats named: the next launch draws the pad's line
EXPECT Crew: 'Ace' aboard 'two capsules' part 0 (1/3)
EXPECT [vab] launched 'two capsules' (1 parts)

FORBID Segmentation
FORBID FAILED
FORBID GL_
