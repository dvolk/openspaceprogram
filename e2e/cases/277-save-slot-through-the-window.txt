# The Save/Load window is the game's own save path. Until this case, no case
# clicked its Save button: the save coverage went through the CLI flags
# (--save, --resave, and the retired --reload), so the slot field and the Save
# button could have been deleted without a single case noticing.
# Found by scanning the live registry against the paths the cases actually click
# (tmp/ui_coverage.py) -- the same way "Recover Vessel" turned out to be uncovered.
#
# The slot name is typed rather than left at its default. The field opens holding
# "save1", so a save landing in a directory named exactly 'myslot' is what proves
# the typing REPLACED it: --ui-type selects all before typing, and without that
# the characters would append and the slot would be 'save1myslot'.
#
# Nothing is flown here -- a new game in the Space Center has no ship -- so the
# save holds zero vessels. That is a real state a player can save into, and case
# 270 owns what a no-ship save must record.
NAME save-slot-through-the-window
ARGS --timeout 8
ARGS --ui-click 1500,"Title Menu/New Game"
ARGS --ui-click 2200,"New Game/Start"
ARGS --ui-click 3000,"Game Menu/Save/Load"
ARGS --ui-type 3800,"Save/Load/##newslot",myslot
ARGS --ui-click 4400,"Save/Load/Save##saveload"
EXPECT [game] new game 'game1'
CHECK re.search(r"Saved 0 ship\(s\) to \S+-game1/myslot \(game 'game1'\)", out)
FILE saves/*/myslot/save.json
NOFILE saves/*/save1myslot
FORBID FAILED
FORBID GL_
FORBID error:
