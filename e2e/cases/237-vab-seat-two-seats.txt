# One person in two seats. The window greys the second one out, but the plan can
# still go stale -- a system switch empties the pad, an earlier launch took the
# suit away. The launch is REFUSED before the ship exists rather than built with
# a seat the pad cannot fill, because a ship that flies half-crewed reads like a
# success.
#
# This one keeps --vab-assign, and it is the exception rather than the rule: the
# seat dropdown lists an already-seated person as "Ace  (seated)" inside a
# BeginDisabled (gameui.cpp:3663), so no click can name the same person twice.
# The refusal is not a gate the UI has and the hook duplicates -- it is the
# guard for a plan that went stale under the player, which the UI cannot build
# on purpose. --vab-assign is how the case gets the plan into that state.
NAME vab-seat-two-seats
ARGS --vab-empty --kerbals e2e/fixtures/three_kerbals.json
ARGS --time-accel 1 --timeout 12 --frame-cap 30
ARGS --ui-click 1000,"Capsule (3m)##capsule_r1.5h3"
ARGS --sim-mouse 2000,0,960,540,LMB
ARGS --vab-assign 3000,0,0,Ace --vab-assign 3500,0,1,Ace --ui-click 6000,"VAB TopBar/LAUNCH"
EXPECT [vab] launch refused: 'Ace' cannot sit in two seats
EXPECT [toast] Launch refused: 'Ace' cannot sit in two seats
FORBID [vab] launched
FORBID Crew:
FORBID Assertion
FORBID Segmentation
FORBID GL_
FORBID error:
LIMIT 90
