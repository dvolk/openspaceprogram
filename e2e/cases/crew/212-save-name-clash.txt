# #266, proven from the other side: a save with TWO VEHICLES named 'Ash' -- the
# crewed ship in v0 and an uncrewed copy in v1. The live game cannot produce this
# (dedupVehicleName refuses the name), so the fixture is hand-authored from
# save_roster_named: rename v0, copy its ship into v1 with fresh part uids and no
# seat, and offset it 300 m along the track.
#
# Every reference here is a SLUG, so the load must make the CREWED ship (v0)
# active no matter what either of them is called. Measured against the old
# name-keyed load on the same shape: byName['Ash'] held whichever of the two was
# built last -- v1, the uncrewed copy -- so the active vehicle came back with
# nobody aboard. The load line now prints the slug alongside the name, which is
# what says WHICH 'Ash' -- the name alone cannot.
NAME save-name-clash
CLAIM A save with two ships named alike is refused rather than merged.
KIND invariant
ARGS --timeout 10
# Reached by the Save/Load sheet, not --load: Game Debug ticks the e2e
# fixture root, the sheet picks the "fixtures" game, the slot filter
# narrows the fixture list to this one row, and row + Load button do
# the rest. Same load_game() either way, so the assertions below are
# unchanged. The PERIOD presses climb
# the warp ladder where --time-accel used to: a sheet
# load starts paused.
ARGS --sim-press 500,0,F1
ARGS --ui-click 1000,"Game Debug/Load e2e fixture saves"
ARGS --sim-press 1500,0,F1
ARGS --ui-click 2000,"Title Menu/Save/Load"
ARGS --ui-click 2500,"fixtures"
ARGS --ui-type 3000,"Save/Load/##filter",save_name_clash
ARGS --ui-click 3800,"save_name_clash"
ARGS --ui-click 4000,"Save/Load/Load##saveload"
ARGS --sim-press 4300,0,PERIOD
EXPECT [crew] loaded 'Ash' aboard 'Ash'
EXPECT Loaded game from e2e/fixtures/save_name_clash (active: Ash) [v0]
EXPECT [toast] Loaded fixtures/save_name_clash
FORBID (active: Ash) [v1]
FORBID [load] refused
FORBID error:
FORBID FAILED
LIMIT 60
