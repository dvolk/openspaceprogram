# The same rule case 225 pins at boot, on the path a player actually reaches it:
# the VAB lets you bolt parts onto a kerbal part, so LAUNCH has to refuse rather
# than place a two-part "person" (which the save writer would silently shrink to
# one part, and boarding would abort on). A toast, not a crash, and the editor
# stays open with the build intact.
NAME vab-launch-kerbal-multidef
CLAIM The VAB refuses to launch a multi-part kerbal with a toast.
KIND invariant
ARGS --ui-click 10000,"VAB TopBar/LAUNCH" --timeout 13
# Reached the way a player reaches the editor: Title Menu -> New Game -> Start, then
# the 4 key.
# Game Debug turns on dev vehicles, which is what puts this def in the
# Load picker; the filter narrows the roster to one row, and row + Load
# do the rest. Same vabLoad() either way, so the assertions below are
# unchanged -- and every scripted event here is shifted +7000ms because
# the editor opens at 2.6s, not at boot.
ARGS --ui-click 1000,"Title Menu/New Game"
ARGS --ui-click 1600,"New Game/Start"
ARGS --sim-press 2600,0,4
ARGS --sim-press 3100,0,F1
ARGS --ui-click 3600,"Game Debug/Dev vehicles in the VAB picker"
ARGS --sim-press 4100,0,F1
ARGS --ui-type 4600,"VAB TopBar/##vehfilter",kerbal_rover
ARGS --ui-click 5100,"VAB TopBar/##vabload"
ARGS --ui-click 5700,"kerbal_rover"
ARGS --ui-click 6300,"VAB TopBar/Load"
EXPECT [vab] entered the editor (sim keeps coasting)
EXPECT [vab] launch refused: 'kerbalrover' is kerbal-rooted but has 2 parts
EXPECT [toast] Launch refused: a staff member must be a single part
FORBID [vab] launched
FORBID error:
FORBID FAILED
LIMIT 60
