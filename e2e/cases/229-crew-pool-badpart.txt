# A crew_pool entry naming a fuel tank is data, not a person. The pool is built
# OFF the pad and committed only once the whole load succeeds, so this refusal
# leaves the RUNNING cast standing: the launch after it still gets a kerbal.
# Before the transaction the pad was cleared and refilled from the file first,
# so a refused load left the career holding a stranger's crew -- or nobody.
NAME crew-pool-badpart
ARGS --kerbals e2e/fixtures/three_kerbals.json --time-accel 1 --timeout 14 --frame-cap 30
ARGS --startship racer,res/ships/racer.json,Kerbin,rot-orbit
ARGS --recover-anywhere
# Two ESCs, because the key means different things per scene: the first pops the
# VAB the boot pushed (the --vab below is what opens it), the second is the flight
# hub that carries "Recover Vessel".
ARGS --sim-press 1900,0,ESCAPE --sim-press 2100,0,ESCAPE
ARGS --ui-click 2300,"Game Menu/Recover Vessel"
ARGS --reload e2e/fixtures/save_crew_pool_badpart --reload-at 3000
ARGS --vab res/ships/tanker.json --ui-click 5000,"Game Menu/VAB" --ui-click 7500,"VAB TopBar/LAUNCH"
EXPECT [load] refused e2e/fixtures/save_crew_pool_badpart
EXPECT crew pool entry 'fuel_tank' is a 'fuel_tank' part, not a kerbal
EXPECT [vab] launched 'tanker' (7 parts)
EXPECT Crew: 'Bram' aboard 'tanker' part 0 (1/1)
FORBID FAILED
FORBID no kerbal left
FORBID Assertion
FORBID Segmentation
FORBID GL_
FORBID error:
