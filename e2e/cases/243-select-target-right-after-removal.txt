# A target row borrows its vessel's name pointer, so a removed ship must leave
# the list at once: the planner only rebuilds it in the state pass, and anything
# that scans the list in between used to read freed memory (asan: UAF in
# selectTargetByName, strlen on Vehicle::name). The --select-target hook is that
# scanner, and it now runs AFTER the state pass so it sees this frame's list.
# Pin the behaviour the fix guarantees: a selection made a frame after a
# sibling's removal names the vessel it names, at the shifted index -- not the
# row its name pointer used to occupy.
# --frame-cap 4 keeps the removal and the selection in adjacent frames, which is
# where the stale row used to be visible.
NAME select-target-right-after-removal
ARGS --time-accel 1 --timeout 12 --frame-cap 4
ARGS --startships e2e/fixtures/pad_four.json --kerbals e2e/fixtures/tiny_kerbals.json
ARGS --tracking 2000
ARGS --ui-click 4000,"Tracking Ship List/x##rm_pad two"
ARGS --select-target 4300,"pad three"
ARGS --xfer-log --orbit-interval 1
EXPECT Removed 'pad two' (active unchanged: pad one)
EXPECT [target] hook: selected "pad three" (index 2)
CHECK re.search(r"Removed 'pad two'.*target=\"pad three\"", out, re.S)
FORBID not in the target list
FORBID target="pad four"
FORBID Cannot remove
FORBID Assertion
FORBID Segmentation
FORBID GL_
FORBID error:
LIMIT 90
