# The rotating render frame, which case 194 cannot pin: there ship->frame IS the
# focus body's inertial frame, so GetOrientRelTo returns identity and a missing or
# transposed inertial->render-frame transform still passes. Here the frame is the
# body's ROTATING one, and the answer is known exactly: the equator plane's normal
# is the body's own +Y, so n_ref must read (0,1,0) while [mapdump] shows that same
# normal tilted by the obliquity in the inertial frame. Drop the transpose, or
# transpose the wrong way, and n_ref comes back the tilted one -- this CHECK fails
# on the first line.
#
# The orbit normal then precesses around the pole as the ground turns under it,
# keeping a constant angle to it: n_orb.y is cos(Inc) and must not drift.
NAME orbit-plane-rot-frame
ARGS --time-accel 1 --timeout 8 --startship racer,res/ships/racer.json,Kerbin,rot-orbit
ARGS --plane-log --orbit-log --orbit-interval 1 --map-dump 6000
ARGS --sim-press 1500,0,ESCAPE
ARGS --ui-click 2500,"Game Menu/Settings"
ARGS --ui-click 3500,"Settings/Orbital plane"
EXPECT [planelog]
FORBID FAILED
FORBID GL_
FORBID error:
CHECK len(plane) > 3
CHECK all(p["frame"] == "rot" for p in plane if p["t"] > 1.0)
# The pin: in the body's own axes the equator's normal IS +Y.
CHECK all(abs(p["n_ref"][0]) < 1e-6 and abs(p["n_ref"][1] - 1.0) < 1e-6 and abs(p["n_ref"][2]) < 1e-6 for p in plane if p["t"] > 1.0)
# The inertial normal it was transformed from is NOT +Y: the obliquity is real
# (23.44 deg, so its y is cos of that), and the line above is not vacuous.
# [mapdump] rows are slot order: 0 = equ.
CHECK abs(mapb[0]["n"][1] - 1.0) > 0.05
# The orbit normal keeps a constant angle to the pole while its x/z precess as
# the ground turns: y steady, z visibly moving.
CHECK max(p["n_orb"][1] for p in plane if p["t"] > 1.0) - min(p["n_orb"][1] for p in plane if p["t"] > 1.0) < 1e-4
CHECK max(p["n_orb"][2] for p in plane if p["t"] > 1.0) - min(p["n_orb"][2] for p in plane if p["t"] > 1.0) > 1e-5
CHECK all(p["ticks"] == "drawn" for p in plane if p["t"] > 1.0)
