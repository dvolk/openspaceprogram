# #231: one deck, one ship. Two grounded ships sit inside each other's 10 m
# grounded proximity radius, so a second ship placed on an occupied pad wakes
# the pair on the first tick and they torque each other -- the stack is a
# collision, not a cosmetic overlap. vabLaunch therefore rays the deck's
# footprint before placing anything, and refuses while something stands on it.
#
# Two details are pinned by this refusal and one was a real bug: the sample
# grid has to include the pad centre (the VAB places a ship dead on the pad and
# a part is only ~2.3 m across, so a grid of +-10/+-30 misses it outright --
# dropping the 0 back out makes this case launch instead). The clear-pad path
# is case 52; that a ship on ANOTHER pad does not block this one is case 165.
NAME vab-pad-occupied
ARGS --vab res/ships/tanker.json --startship racer,res/ships/racer.json,Kerbin,pad
ARGS --vab-launch 2000 --timeout 12
EXPECT [vab] launch refused: 'racer' occupies 'main_space_port'
EXPECT Launch refused: racer is on Main space port
FORBID [vab] launched
FORBID GL_
FORBID error:
