# #231: one deck, one ship. Two grounded ships sit inside each other's 10 m
# grounded proximity radius, so a second ship placed on an occupied pad wakes
# the pair on the first tick and they torque each other -- the stack is a
# collision, not a cosmetic overlap. vabLaunch therefore rays the deck's
# footprint before placing anything, and asks what to do about it.
#
# Two things are pinned here. The sample grid has to include the pad centre:
# the VAB places a ship dead on the pad and a part is only ~2.3 m across, so a
# grid of +-10/+-30 misses it outright (drop the 0 back out and this case
# launches instead). And the card's answer is DEFERRED -- it runs on a later
# frame, so the callback re-finds the occupant rather than holding the pointer
# it had when it asked. Clicking "Clear the pad" proves that round trip: the
# re-found ship is the right one, and remove_ship's crew guard is what refuses
# (every pad ship carries crew, so a crew policy is the open half of #231).
# The clear-pad path with no occupant is case 52; that a ship on ANOTHER pad
# does not block this one is case 165.
#
# The second start ship is load-bearing: a seated kerbal is no longer a fleet
# entry (part.h), so with only 'racer' in orbit-and-pad the fleet is ONE vessel
# and remove_ship's last-ship guard answers first -- the case would pass without
# ever reaching the crew guard it exists to pin.
NAME vab-pad-occupied
ARGS --vab res/ships/tanker.json --startship racer,res/ships/racer.json,Kerbin,pad
ARGS --startship probe,res/ships/tanker.json,Kerbin,high-orbit
ARGS --ui-click 2000,"VAB TopBar/LAUNCH" --timeout 12
ARGS --ui-click 3000,"Question/Clear the pad"
EXPECT [vab] launch refused: 'racer' occupies 'main_space_port'
EXPECT [ask] racer is standing on Main space port. Clear the pad?  [Clear the pad | Cancel]
EXPECT [ask] answered 0
EXPECT Cannot remove racer -- EVA its crew out first
FORBID FAILED
FORBID [vab] launched
FORBID Refusing to remove the last ship
FORBID GL_
FORBID error:
