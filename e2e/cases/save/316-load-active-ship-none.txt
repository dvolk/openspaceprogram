# #270: "" and an absent "active_ship" key are DIFFERENT saves. This fixture is
# save_no_active with the key put back as "" -- a fleet of two vessels with none
# of them flown, which is exactly the state recoverActive() leaves (it does no
# handoff to a neighbour, game.cpp). The old reader collapsed both into "take the
# first vessel", so a load invented an active ship the player never had and
# opened the flight scene on it.
#
# Case 213 keeps the OTHER half pinned: the key absent entirely (a hand-edited or
# foreign file) still falls back to the first vessel in save order.
NAME load-active-ship-none
CLAIM An empty active_ship means no vessel is flown; an absent key means pick one.
KIND invariant
ARGS --timeout 8
# Reached by the Save/Load sheet, not --load: Game Debug ticks the e2e
# fixture root, the sheet picks the "fixtures" game, the slot filter
# narrows the fixture list to this one row, and row + Load button do
# the rest. Same load_game() either way, so the assertions below are
# unchanged. The PERIOD presses climb
# the warp ladder where --time-accel used to: a sheet
# load starts paused.
ARGS --sim-press 500,0,F1
ARGS --ui-click 1000,"Game Debug/Load e2e fixture saves"
ARGS --sim-press 1500,0,F1
ARGS --ui-click 2000,"Title Menu/Save/Load"
ARGS --ui-click 2500,"fixtures"
ARGS --ui-type 3000,"Save/Load/##filter",save_active_none
ARGS --ui-click 3800,"save_active_none"
ARGS --ui-click 4000,"Save/Load/Load##saveload"
ARGS --sim-press 4300,0,PERIOD
EXPECT Loaded game from e2e/fixtures/save_active_none (active: (none))
EXPECT [toast] Loaded fixtures/save_active_none
EXPECT [spacecenter] entered
EXPECT [crew] loaded 'Ash' aboard 'racer'
FORBID (active: racer)
FORBID [scene] title -> flight
FORBID Load failed
FORBID [load] refused
FORBID error:
FORBID FAILED
LIMIT 60
