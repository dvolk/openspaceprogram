# #268: the docking INTENT (Vehicle::dockTargetShip + its target port) is a
# slug reference in the save (save.h:170), and nothing pinned that it survives
# a save/load round trip. The old dock coverage could not: case 79's fixture is
# an already-mated pair (ONE merged vessel, no intent left -- the dock consumes
# both halves), and 45/46/47 never save.
# --dock-test approach places the probe 2 m short of capture and this case never
# presses T, so the save is taken with the intent LIVE. The Save window writes
# the loaded game back out and FILE reads what the game actually wrote (#271).
# The target PORT uid is deliberately not asserted: part uids are not stable
# across a load (every cross-part reference is remapped through
# savedUidToPart), so the re-emitted uid is expected to differ from the
# fixture's 15. The slug is the thing that must survive.
NAME dock-intent-survives-save-load
CLAIM A docking intent survives save/load.
KIND invariant
ARGS --timeout 11
ARGS --sim-press 6200,0,ESCAPE
ARGS --ui-click 6600,"Game Menu/Save/Load"
ARGS --ui-type 7200,"Save/Load/##newslot",slotR
ARGS --ui-click 7800,"Save/Load/Save##saveload"
# Reached by the Save/Load sheet, not --load: Game Debug ticks the e2e
# fixture root, the sheet picks the "fixtures" game, the slot filter
# narrows 50 saves to this one row, and row + Load button do the rest.
# Same load_game() either way, so the assertions below are unchanged --
# and every scripted event here is shifted +5000ms because the load now
# lands at 4s, not at boot. The PERIOD presses climb the warp ladder
# where --time-accel used to: a sheet load starts paused.
ARGS --sim-press 500,0,F1
ARGS --ui-click 1000,"Game Debug/Load e2e fixture saves"
ARGS --sim-press 1500,0,F1
ARGS --ui-click 2000,"Title Menu/Save/Load"

ARGS --ui-type 3000,"Save/Load/##filter",save_dock_intent
ARGS --ui-click 3800,"save_dock_intent"
ARGS --ui-click 4000,"Save/Load/Load##saveload"
ARGS --sim-press 4300,0,PERIOD
