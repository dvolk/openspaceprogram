# The Recorder readout (#990): a point on the graph becomes a number.
#
# The window normalises every visible channel onto its OWN min..max, so a line's
# height carries shape and timing but no value, and no label can carry one either
# -- implot hashes the whole plot-item label, which is what made the first version
# of this window churn colours and grow its item pool every frame (kRecChans spells
# that trap). So the value belongs to a SAMPLE instead: click the graph and the
# window prints that sample's readings, through the one formatter that also draws
# the rows -- which is what makes a dash a dash here exactly as it is a dash in the
# file.
#
# Four claims, all of them about the number rather than the pixels:
#
#   1. The click lands on the sample the pointer is over, on the MISSION clock:
#      t=23.00 s sits inside the ring's 19 s span, the same x axis the plot pins to.
#      Not the file's t= column (recorder.h shouts about that in capitals), so a
#      warp coast keeps the pointer proportional.
#
#   2. The numbers are the ring's own, and therefore the trace's: ONE sampler feeds
#      both sinks (#966/#972's rule), so alt_asl=268.469 v=0.0142148 here is the row
#      the flight log wrote at that moment, not a second reading taken for the
#      picture. They print as %.6g, enough digits to tell 45210 from 45211.
#
#   3. A channel toggled on appears in the pinned line -- gamma= is here because the
#      click came after the toggle. The toggle is the same hud.rec_chan state the
#      checkboxes set, so the printed line and the picture agree about what is drawn:
#      the readout lists the visible subset, in table order.
#
#   4. Unpin releases it, and a DRAG does not pin anything. Both halves begin as the
#      same gesture, so the window has to tell them apart: a press that never
#      travelled parks the pin, a press that travelled has already been handed to
#      implot to pan the graph with. The drag at 9400 ms proves the second half -- it
#      prints fit=off, which is what a real pan prints, and the pin count stays at 1.
#      It runs AFTER the numbered claims above so a view that drifts under a scripted
#      drag cannot move the digits asserted there.
#
# Release is a button rather than a second click because this window cannot promise
# what a pixel means once the pilot has taken the view. Measured in
# tmp/night5/probe_990j.log: after one scripted pan, two clicks in the SAME pixel
# 600 ms apart pinned t=29.00 and then t=22.00, because the x range implot holds
# moved between those frames. A pin that appears to refuse to let go is worse than
# one extra button, and Unpin is greyed while nothing is pinned, exactly like Pause.
#
# The click is scripted with --sim-mouse pixels rather than --ui-click because the
# plot is not a widget, so there is no label to name. The pixel comes from the
# at=/size= the window prints at appearing time (at=496,372 size=560,340), which is
# also what pins its anchor; 776,620 is inside the plot frame the window measures
# for its own wheel/drag test. The Pause at 8000 ms is what makes the click
# deterministic: a live ring keeps growing, so the x range -- and so the sample that
# pixel means -- moves under the cursor between frames.
#
# Why not assert the hover readout instead of the pinned one: hover draws the same
# rows but prints nothing, so it is the eye's business. Pinning is the half that
# leaves evidence, and it is the half a pilot uses to move the pointer away.
#
# WHAT THE PINNED ROW IS (#1132 family D, re-minted 2026_11_24), column by column, because
# this one broke and the digits are worth reading rather than swapping. The sample sits at
# mission t=23.00 s with the stager parked on the pad at alt_asl 268.069 m. That figure did
# move, by 0.4 m, when #1152 took the collision skins off by default: a hull used to stop
# its own margin plus the terrain's away from the ground it stands on, and the row's
# altitude IS that rest height (a stager on the pad reads alt_agl 11.006 now, 11.206 with
# OSP_HULL_MARGIN=0.1 OSP_TERRAIN_MARGIN=0.5). The pad has not moved; the hull sits inside
# where its skin used to stop it. Of the other four columns, two are Kerbin's authored air
# and two are the hull's own residue:
#   q=20.2187 is 1/2 rho tas^2 with rho ~1.194 and tas ~5.82 m/s -- the deck wind read at
#     this altitude (5 m/s at 0 ramping to 40 m/s at 11205 m), not a hull moving at 20 m/s.
#     The row minted before the skin change read 20.2534 at 268.469 m: 0.17% down, which is
#     0.08% of air speed, since q goes as tas^2 and only the altitude moved.
#   aoa=-90.0707 is that same flow arriving broadside at a nose-up hull.
#   v=0.0174538 and gamma=-0.00132029 are the integrator's residue: the hull is standing
#     still, so the speed and flight-path angle are noise at the 1e-2 m/s scale, and they are
#     the two columns that move when anything in the aero or contact law moves. The previous
#     row read 0.0142148 and 0.000217918 for the same still hull; gamma changed sign, which
#     is what a residue that small does.
# So the exact digits are a snapshot of jitter standing in 5.8 m/s of wind, and this file is
# where that fact gets re-minted, not argued: flight/395-surface-aoa-readout is the case that
# pins the wind's numbers as laws. Measured byte-identical across three standalone runs and
# four concurrent ones, so the row is reproducible even though its v and gamma columns are
# residue -- the same schedule on the same build gives the same residue.
# Three of the columns are one number, and the CHECKs below say so without pinning the jitter:
#     sqrt(2 q / rho) = sqrt(2 x 20.2187 / 1.1941) = 5.8193 m/s of air over the hull, while the
#     authored ramp (5 m/s at 0, 40 m/s at 11205 m) reads 5.8373 at alt_asl 268.069 m. The
#     0.018 difference is the row's own v=0.0174538, pointing into the wind -- the residue
#     again, in the third decimal.
# So q and aoa are pinned as bands -- what the air makes, within the jitter of a still hull --
# and only the EXPECT line above pins the digits. A hull moving at 20 m/s would bill ~240, so
# the q band is a claim about the air; aoa within half a degree of -90 is a claim about the
# nose being up and the flow being horizontal.
CHECK (lambda m: 20.0 < float(m.group(4)) < 20.8 and abs(float(m.group(5)) + 90.0) < 0.5)(re.search(r"\[recwin\] pin t=([\d.]+) alt_asl=([-\d.e+]+) v=([-\d.e+]+) q=([-\d.e+]+) aoa=([-\d.e+]+)", out))
