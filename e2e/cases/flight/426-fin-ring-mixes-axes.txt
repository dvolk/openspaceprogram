NAME fin-ring-mixes-axes
CLAIM A cruciform ring of ELEVATORS yaws a hull that owns no yaw-rigged surface: one demanded torque reaches whichever plates lever part of it, while the roll key -- which no plate in that ring levers at all -- still only gets the pod's drum.
KIND invariant
# #426 slice 2: the control surfaces are actuator rows in the ONE actuatorSolve call,
# so PartDef::control_axis is a label for WHICH KEY asks and which axis decides the rig
# sign, not a wall on what the plate can be spent for.
# finring.json is the skiff's airframe with the rudder and ailerons gone and its two
# elevators replaced by four at 45/135/225/315 deg clock -- an X. A plate at 45 deg
# levers pitch and yaw equally (its row is cross(ri, normal) * q*S*cl, and with the
# normal rotated 45 deg about the stack the pitch and yaw components come out equal and
# the roll component r*cos(2*45) is EXACTLY zero). So:
#   - the yaw ask has four plates to answer it, every one of them authored "pitch";
#   - the roll ask has NONE, and falls back on the capsule's 100 N m triad.
# Measured on this run (and --sim-steps puts the [attlog] rows on whole seconds, so the
# windows below are whole seconds too): A (yaw, t=1..2.5) takes the rate about the
# ship's up from 0.0000 to 0.324 rad/s while the key is down and to 0.738 by t=3-4,
# after it released; E (roll, t=3.5..5) never gets past 0.020 rad/s about the nose.
# That roll number is roughly the drum's own answer -- 100 N m over a hull whose inertia
# here is a couple of thousand kg m^2, so a couple of hundredths of a rad/s per second,
# minus whatever the air takes back -- which is also why the yaw pin sits at 0.5 rather
# than a hair over the measured value: an order of magnitude beyond what no-fin hardware
# can do on that axis (0.738 against 0.020 rad/s).
# The 0.05 "before" limit says the hull was not already turning when the key arrived, so
# 0.74 cannot be read as inherited tumbling. The 0.20 roll limit is this same run's
# control: if the mix ever turns into a mode switch, or these rows grow a roll
# component, that one moves.
# #686 re-kerbinned the air this hull flies in (the flying-cruise bed moved with the air
# top, 7.0 -> 8.5 km, and Kerbin now wears a lapse-rate table instead of one 5500 m scale
# height: rho at the spawn row went 0.3478 -> 0.5017 kg/m3, a 1.44x step). Both rate
# windows moved and neither in the direction this case's old text quoted: the yaw peak
# grew (0.64 -> 0.738 rad/s, the plates' torque is q x area x cl and q went up) while the
# rate SAMPLED WHILE THE KEY IS DOWN fell (0.64 -> 0.324), i.e. the hull now lags the ask
# by an extra second. The split is why the yaw pin is two rows now instead of one: the
# in-press floor asks only "the axis is being driven", and the wider window carries the
# "eight times the drum" claim. What this case owns is WHICH axes a demanded torque
# reaches; how fast each one gets there is the air's business.
ARGS --time-accel 1 --startship finring,res/ships/finring.json,Kerbin,flying-cruise
ARGS --att-log --sim-steps 480
ARGS --sim-press 1000,1500,A
ARGS --sim-press 3500,1500,E
LIMIT 90
EXPECT [attlog]
CHECK len(att) >= 6
CHECK max(a["awyaw"] for a in att if a["t"] <= 1.0) < 0.05
# While A is down (1.0-2.5 s) the press window holds one row, t=2: 0.324 rad/s. The
# floor asks only that the axis is being driven. It is NOT a ratio against the row before
# the key: that one prints 0.0000 at four decimals and the CHECK above only keeps it
# under 0.05 rad/s, so dividing by it is meaningless. The comparison this case rests on
# is against the ROLL key's best row -- 0.324 in-press and 0.738 after release against
# 0.020 rad/s about the nose, which is what the last two pins hold.
CHECK max(a["awyaw"] for a in att if 1.2 < a["t"] < 2.8) > 0.25
# The rate the same press reaches once the hull catches up: 0.736 at t=3, 0.738 at t=4,
# back down to 0.289 at t=5 (the key released at 2.5 s). #686 moved the in-press sample
# below the 0.5 this pin used to carry, so the margin claim lives here instead.
CHECK max(a["awyaw"] for a in att if 1.2 < a["t"] < 4.8) > 0.5
# The CEILING on that same window. Without it the yaw pin is one-sided and this run
# still passes if a fin's share starts travelling through actuateAttitude as well as
# through the air -- the double bill #426 exists to avoid, which nearly doubles the yaw
# rate (~1.5 rad/s at this q with the subtraction removed, against 0.738 here).
# tests/test_authority.cpp pins the same thing to four significant figures; this is the
# flight-level guard.
CHECK max(a["awyaw"] for a in att if 1.2 < a["t"] < 4.8) < 1.0
CHECK max(a["awroll"] for a in att if 3.5 < a["t"] < 5.5) < 0.20
