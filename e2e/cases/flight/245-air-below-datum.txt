# airDensity() used to answer VACUUM at or below a body's sea-level datum, and that
# one answer took drag, lift and jet thrust off a hull together (#245). The datum is
# radius + the authored sea_level (terrain.h). No shipped system authors a non-zero
# sea_level, so there it is the bare radius -- and relief is SIGNED about the radius
# (terragen.h:terrainRelief, whose noise floor is -amplitude/3) with only ocean_mode
# "flat" clamping it, so Kerbin's sea beds sit under its datum and so do the valleys of
# the DRY air bodies: Eve (amplitude 5000, rho0 1.7), Mars, Titan. Sub-datum flight was
# never a future-authoring problem, and no test could see it.
# e2e/fixtures/systems/245-kerbin-sea.json raises Kerbin's sea_level to 600 m, which
# puts the space port itself 336 m UNDER the datum: alt_asl 264.0 -> -336.2 while
# alt_agl stays 8.6, and bme flips to "ocean" (terragen.h: has_sea and alt <= 0 reads
# as Ocean). This case parks the skiff there and asks what the air is. Before the fix
# every [drag] row read rho=0.0, |F|=0.00 N, |L|=0.00 N and the jet printed
# thrust=0.0N -- a plane at the densest point of the model's atmosphere, in vacuum.
# --sim-steps, not --timeout: the hull's post-ignition tumble is chaotic, so a
# wall-clock log gate samples it at a different phase each run (measured: the same ARGS
# sampled max |F| 3.1 kN one way and 12.4 kN another). Logic-tick gating puts the rows
# at t=1..15 s identically, run to run.
NAME air-below-datum
CLAIM At or below a body's sea-level datum the air is its sea-level density, flat: a hull under the datum gets rho0, its drag, its lift and its jet thrust.
KIND invariant
ARGS --system e2e/fixtures/systems/245-kerbin-sea.json
ARGS --startship skiff,res/ships/skiff.json,Kerbin,pad
ARGS --info-log --drag-log --drain-log
ARGS --sim-press 500,3000,R
ARGS --sim-press 500,20000,T
ARGS --sim-steps 900
LIMIT 60
EXPECT [drag]
CHECK len(drag) == 15
CHECK len(drainlog) >= 15
CHECK len(surf) == 15
# THE WORLD: the space port sits under the datum on this fixture (it parks at alt_asl
# 264.0 on the shipped Kerbin, whose datum is the bare radius). Nothing in this run
# leaves sub-datum air, and no row of it is near the datum where the two laws nearly
# agree. These two are the only rows that describe the WORLD rather than the air, and
# they are the two the pre-fix binary still passes.
CHECK all(s["alt_asl"] < -300.0 for s in surf)
CHECK all(s["bme"] == "ocean" for s in surf)
# THE LAW: rho == the authored sea_level_density on every row, and never ABOVE it.
# Flat, not the exponential continued downward -- that reads 1.302 kg/m3 at this
# hull's -336 m and 1.321 at its -424 m (against 1.225 measured), and 115 kg/m3 at the
# -25 km the unit test pins. The 1e-3 band is a 6-8% rejection here, thin on purpose
# relative to tests/test_drag.cpp, which owns the deep case.
CHECK all(abs(d["rho"] - 1.225) < 1e-3 for d in drag)
CHECK all(d["rho"] <= 1.225 + 1e-9 for d in drag)
# IT PUSHES: 5.6 kN of fan thrust drives the hull through that air, and the bill
# follows (max |F| 19.2 kN, 85.9 kN summed over the 15 rows). The sum is the
# phase-insensitive half; both are 0.00 N on every row under the pre-fix law. And the
# hull actually travels: the slide takes it from the pad's -336 m down to -424 m, which
# is a long way from the datum where the flat and continued profiles nearly agree.
CHECK max(d["F"] for d in drag) > 5000.0
CHECK sum(d["F"] for d in drag) > 20000.0
CHECK max(d.get("L", 0.0) for d in drag) > 5000.0
CHECK min(s["alt_asl"] for s in surf) < -400.0
# IT BREATHES: jetAirGate reads rho/rho_sea, so the same answer starved the engine.
# The r0.25h1 fan is rated 5625 N at full gate; at -336 m it runs at full gate (max
# 6.6 kN with the ram term in).
CHECK max(r["thrust"] for r in drainlog) > 5000.0
# IT IS THE SAME AIR THE ATLAS PRINTS (#552 A3): --drag-log now carries the T/p/a the
# body's authored scale height IMPLIES, through the same dragAtm seam the dossier uses,
# so the two cannot mean different airs. Under this datum p is FLAT (the #618 call), so
# every row reads rho0 g H = 1.225 x 9.81 x 5500 = 66094.9 Pa beside 188.0 K and
# 274.8 m/s. Mach divides the AIR-relative speed at the COM -- the flow every q= on the
# [surface] rows is billed from, not necessarily the |v|= on the line, which is the
# frame speed (#97). This hull never leaves Kerbin's rot frame, where the air is at
# rest, so here the two are the same number and the per-surface mach= agrees with the
# hull Mach= to the digit (t=8: |v|=37.06, Mach=0.135, wing_l mach=0.134). The pad row
# reads 0.002; the post-ignition tumble peaks at 0.286, so this hull nowhere approaches
# compressible flow. Before A3 none of this was measurable from the harness at all: the
# only way to check it was to read the source.
CHECK all(abs(d["airT"] - 188.0) < 0.05 for d in drag)
CHECK all(abs(d["airP"] - 66095.0) < 1.0 for d in drag)
CHECK all(abs(d["airA"] - 274.8) < 0.05 for d in drag)
CHECK all(0.0 <= d["mach"] < 0.6 for d in drag)
CHECK max(d["mach"] for d in drag) > 0.2
# MUTATION: airDensity() back to `alt <= 0.0 -> 0.0` (the #245 law, with this fix's
# vehicle.cpp early-out already gone, so drag.h is the whole question). Six checks go
# red together -- rho, max |F|, sum |F|, |L|, thrust, and the depth, because with no
# air the jet never lights and the hull never leaves the pad. The two WORLD checks stay
# green: the datum, the biome and the pad's altitude never moved, only the air's answer
# did. That is the shape this case is built to have.
# tmp/aero/n245b_e2e_mut.log (mutant binary tmp/aero/osp_mut1).
# That mutant predates the five A3 checks, so they are not in that count. Read off the
# code rather than re-run: all five go red too, but not because the law moved the air
# numbers -- with rho answering 0 the line takes its DASHED branch (the gate is
# lastDragRho > 0), so the four keys are simply absent from the row. T/p/a themselves
# are set above the density floor and would print unchanged if the row printed them at
# all; max Mach goes red for the same indirect reason thrust does, because a hull whose
# fan never lights never leaves the pad.
