# #378: mid-flight the Save/Load sheet was DRAWN but had no opener. It sits in
# the flight window set, so its draw call ran every frame, yet the only button
# that opens it lives in the title and hub menu windows and inList=false kept it
# out of the Windows panel. A pilot could only F5 into the quicksave pool or ESC
# out to the hub first; Settings and Controls were unreachable the same way.
#
# The route is the Windows panel: it lists the scene's OWN window set, so the
# three shared windows get a row wherever they are drawn, and the menu buttons
# stay as they were.
#
# This is the player path the issue asked for -- a mid-flight save clicked
# through the sheet rather than a hotkey. Case 277 clicks the same Save button
# from the hub with nothing flying; the flight half (a live vessel landing in a
# named slot) is this case. The typed name matters: the slot field opens holding
# "save1", so a slot named slot378 also proves the typing replaced the default.
NAME save-load-from-flight
CLAIM Mid-flight the Windows panel opens the Save/Load sheet and its Save button writes the flying ship into the named slot.
KIND invariant
ARGS --timeout 9
ARGS --startship racer,res/ships/racer.json,Kerbin,rot-orbit
ARGS --ui-click 3000,"Windows/Save / Load"
ARGS --ui-type 4500,"Save/Load/##newslot",slot378
ARGS --ui-click 5200,"Save/Load/Save##saveload"
EXPECT path="Windows/Save / Load"
EXPECT Saved 1 ship(s) to
# The toast names the game's DISPLAY name ("game1"), not the minted directory
# ("20261022_181812-game1") that the Saved line above prints, so the match
# allows either.
CHECK re.search(r"\[toast\] Saved to \S*game1/slot378", out)
FILE saves/*/slot378/save.json
NOFILE saves/*/save1
FORBID FAILED
FORBID error:
