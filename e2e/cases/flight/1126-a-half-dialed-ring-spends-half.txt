# THE MIDDLE OF THE POINTING DIAL (#1126). #1124 shipped one number, rcs_attitude_frac,
# that is supposed to cover four things at once: the readouts, the ask, the solve's bounds
# and the kilograms of hydrazine. Its two ends are pinned. flight/1124-d pins 0 % -- no
# torque, no gram, and a ring that is present-but-unallowed rather than absent -- and
# flight/1124-c plus #1130's cases pin the READOUT half at every dial. The spend leg in the
# MIDDLE rested on one assert and one zero:
#
#     src/vehicle.cpp, actuate side:  assert(rset[i] <= a.rcs[i].limit * (1 + 1e-9))
#
# which is two different weaknesses in one line. It is gone in any NDEBUG build (#1065 is
# the open question about whether that is true here), and it is a BOUND, not a proportion:
# an applier that dimmed the readouts but re-derived its own fraction from the nozzle
# ratings somewhere else would sit comfortably under that bound and keep every pin in the
# repo green. Only 1124-d's exact zero would notice, and only at the end of the travel.
#
# So: the same fixture and the same press as flight/677, one click off full throttle.
# Measured, and this case is the middle row of that table:
#
#   --rcs-att-frac   max tau_spent   max drain kg/s   drain integral   peak |w| rad/s
#   1.0 (flight/677) 138 N m         0.056            0.095-0.10       ~1.05
#   0.5 (this case)   69 N m         0.028            0.048            0.5422
#   0.25              35 N m         0.014            0.024            0.2712
#
# 138 is the ring's own pitch rating (a --steering-log run prices rcs_test at 276/138/138
# N m R/P/Y), so the dial's line is literal: half the authority, half the torque the
# hardware delivers, half the propellant it costs. The two ends of the ratio live in
# different cases because a case is one run of one binary; 677 holds the top row, 1124-d
# holds the bottom, and this holds the middle. What makes the three together a pin rather
# than three numbers is that 69 and 0.028 are each EXACTLY half of 677's figures at a print
# precision fine enough to see it (tau prints at %.0f, the drain rate at %.3f).
#
# The SHAPE is the other half of the claim, and it says the dial cuts the demand and caps
# the hardware, not that it dims nozzles after the fact:
#
#   [slew] t=3.117 mode=stick   tau_ask=69   tau_spent=69     <- the tap: asked = spent
#   [slew] t=6.150 mode=killrot tau_ask=6282 tau_spent=69     <- the hold: capped at 69
#
# The tap's rows ask exactly what the dimmed rows ALLOW and spend all of it, because
# killRotDemand's counterpart for the stick is budgeted from the authority rows (#1130).
# The hold's rows ask 91x what they get: kill-rot budgets from I*(-w)/h, so the demand
# towers and the dimmed ceiling is what answers it. tau_ask stays huge while tau_spent
# flattens at the cap -- the same ask>0/spent=0 shape 1124-d reads at 0 %, at half height.
#
# The bill is read off --drain-log rather than [fuel] for the reason 677 spells out: [fuel]
# prints one decimal and the whole maneuver costs under 0.1 kg, so the tank never appears to
# move. --no-paint because nothing here is a picture (#666 proved the numbers hold without it).
NAME half-dialed-ring-spends-half
CLAIM At half pointing authority this ring spends half: 69 N m of torque and 0.028 kg/s of hydrazine, exactly half of what flight/677 spends at full on the same press (#1126).
KIND invariant
ARGS --time-accel 1 --startship rcs_test,res/ships/rcs_test.json,Kerbin,inertial-orbit
ARGS --slew-log --drain-log --no-paint --rcs-att-frac 0.5
ARGS --sim-press 3000,600,S,6000,3000,X
ARGS --timeout 12
LIMIT 40
EXPECT [slew]
EXPECT [drainlog]
FORBID error:
CHECK len(slew) >= 15
CHECK all(s["mode"] == "killrot" for s in slew if s["t"] > 6.0)
# THE TAP SPENDS THE DIMMED CEILING, in full. Equality of the two columns is the point: the
# ask was cut before it reached the ring, so nothing is left on the table. +-1 because both
# print at %.0f and 69 is this fixture's golden, not a rounding boundary.
CHECK sum(1 for s in slew if s["mode"] == "stick") >= 4
CHECK all(abs(s["tau_ask"] - 69.0) <= 1.0 and abs(s["tau_spent"] - s["tau_ask"]) <= 1.0 for s in slew if s["mode"] == "stick")
# THE HOLD IS CAPPED, NOT SILENCED: kill-rot still asks 4 orders of magnitude more than the
# half ring can answer (6282 N m at the first hold row), and what comes back is 69. At 0 %
# (1124-d) the same rows read ask=5 / spent=0; at 50 % they read ask=huge / spent=69.
CHECK max(s["tau_ask"] for s in slew if s["mode"] == "killrot") > 1000
CHECK max(s["tau_spent"] for s in slew) > 64.0
CHECK all(s["tau_spent"] <= 72.0 for s in slew)
# THE BILL FOLLOWS THE TORQUE, not the readout: 0.028 kg/s against 677's 0.056 kg/s at the
# same moment of the same maneuver. +-0.003 around half, and the integral over the run under
# half of 677's 0.15 ceiling with a floor so a build that spent torque but charged nothing
# still reddens here. (Rate x dt is an upper bound on the kilograms, not the burn -- #1143.)
CHECK 0.025 <= max(r["rates"][0] for r in drainlog) <= 0.031
CHECK 0.02 < sum(r["rates"][0] * r["dt"] for r in drainlog) < 0.075
# WHAT THE HALF BUY IS HALF A SLEW: 0.54 rad/s from the same 600 ms tap where 677 reaches
# ~1.05, and still put down flat before the key comes up at 9.0 -- half authority is a
# slower hull, not a hull that never stops.
CHECK 0.40 < max(s["wnorm"] for s in slew) < 0.65
CHECK all(s["wnorm"] < 0.02 for s in slew if s["t"] > 8.0)
