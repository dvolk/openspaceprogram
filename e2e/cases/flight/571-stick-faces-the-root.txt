# The ship's frame is the ROOT part's, not whichever wheel comes first in the
# parts list (#571). A side mount rolled by the "angle" shorthand does not TILT a
# part -- surfaceMatingRot keeps the child's +Z parallel to the parent's +Z projected
# into the contact plane, and that projection is the parent's +Z itself when the
# contact normal is transverse, which it always is for `angle`/`z` -- so the hull's
# only wheel here (bolted to the tank at angle 90) keeps the ship's nose while its
# "right" axis is the ship's UP axis. Read the stick in that part's frame and W/S yaw
# the ship while A/D pitch it. (An authored "point"/"normal" contact CAN tilt a part;
# tests/test_shipload pins this fixture's shape against the real solver so the
# geometry argued here cannot quietly change under the case.)
#
# att_log prints the frame the controls speak (nose/right/up, #571) and run.py
# resolves the angular rate onto it as wpitch/wyaw/wroll, which is what lets this
# case separate the two at all. Measured on this fixture, --time-accel 1 --sim-steps
# 720, components resolved on the ROOT's axes (tmp/aero/n571_table.py):
#
#   hold S, 2-5 s:  |w| 3.03 = right 3.03 (1.00) + up 0.0002 + nose 0.0001
#   hold A, 6-9.5s: up rises from 0.0001 to 1.16 rad/s
#
# With the stick read off the wheel instead, the same S press gives right 0.99 (0.26)
# and up 3.56 (0.93) -- the ship yaws. That comparison needs care: pointing
# attitudeRef() at the wheel also moves the axes att_log prints, so the mutant's own
# rows label the ship's UP axis "right" and vice versa. tmp/aero/n571_table.py does
# the swap; feeding the mutant's rows straight into the checks below still turns three
# of the five red (tmp/aero/n571_e2e_mutate2.py), which is the point.
#
# The S press is the clean discriminator because the hull's response to a driven wheel
# is only clean along a principal axis, and this tank's right axis is one while its up
# axis is not (a wheel is bolted to its side). The A press is therefore pinned as the
# GROWTH of the yaw component rather than as a clean yaw: 0.8 rad/s of rise sits
# between the 1.16 the root's frame produces and the 0.44 the wheel's frame does --
# there, A is the pitch key, so the up component barely moves while the right one
# grows. What does NOT bite is comparing yaw growth against pitch growth inside one
# run: under the old frame both labels rotate with the frame, so that check passes
# either way and is deliberately not here.
NAME stick-faces-the-root
CLAIM W/S pitches about the ROOT's right axis and A/D yaws about its up axis, even when the hull's only wheel is mounted on its side.
KIND invariant
# --sim-steps, not --timeout: the CHECK windows below are keyed to the printed t, while
# the press schedule and the log cadence run on their own clock. Pinned to 720 ticks
# (12 s at --physics-hz 60) all three clocks are the same clock, so the windows cannot
# be missed by a stalled frame -- and an empty window is a raised max(), not a soft
# result. Same reason the other measurement cases (flight/563, 454, 490) step.
ARGS --time-accel 1 --sim-steps 720
ARGS --startship sideways_wheel,res/ships/sideways_wheel.json,Kerbin,rot-orbit
ARGS --att-log --orbit-interval 0.3
ARGS --sim-press 2000,3000,S
ARGS --sim-press 6000,3000,A
EXPECT [attlog]
FORBID error:
CHECK len(att) >= 10
# The S press: all of it about the ship's own right axis.
CHECK max(a["awpitch"] for a in att if 2.5 < a["t"] < 5.0) > 1.0
CHECK max(a["awyaw"] for a in att if 2.5 < a["t"] < 5.0) < 0.05 * max(a["awpitch"] for a in att if 2.5 < a["t"] < 5.0)
CHECK max(a["awroll"] for a in att if 2.5 < a["t"] < 5.0) < 0.05 * max(a["awpitch"] for a in att if 2.5 < a["t"] < 5.0)
# The A press has to YAW the ship: the up component starts at ~0 and has to rise by
# more than 0.8 rad/s (measured 1.16 on the root's frame, 0.44 with the old one).
CHECK max(a["awyaw"] for a in att if 6.5 < a["t"] < 9.5) - max(a["awyaw"] for a in att if 5.0 < a["t"] < 6.0) > 0.8
