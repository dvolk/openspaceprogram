# [surfinfo] aoa= is the SURFACE window's AoA: the aero law's own alpha (drag.h
# AeroFrame), air-relative flow against the nose. Two ways it goes wrong: a parked ship with
# calm air has no "flow" at all -- integrator jitter only (~1e-4 m/s measured) -- so atan2
# would hand back a number that means nothing, and outside an atmosphere there is no flow to
# have an angle to. Both must read "-", not a number (kAoAFlowFloor, constants.h).
# THE WIND CHANGED WHICH ROWS ARE WHICH (#688, #718). Kerbin authors 5 m/s of east air at the
# deck ramping to 40 m/s at 11 km, so a hull parked nose-up on the pad is not at rest in calm
# air: it stands in 5.8 m/s of it. Its flow is real, so all three angles print, and the case's
# dash half moved to flight/395-angles-dash-above-the-air -- which is the same rule sampled
# where there really is no air. What this case pins now is that the numbers are the WIND's:
# broadside at the pad, and shrinking to the wind's own angle as the climb outruns it.
# AND THE WIND TURNS THE HULL OVER (#1132 family D, re-measured 2026_11_23). A tall blunt
# stack nose-up presents A = 9.87 m2 of side with its area centroid below its CoM, so 5.8 m/s
# of air bills |F| = 236.1 N (Cd 0.985) and |tau| = 41.9 Nm before the engine even lights
# ([drag] t=0.9s, |v| = 0); mid-climb that torque reaches 804.5 N m. #1208 re-measured the
# parked row: it read |F| = 227.9 N at Cd 0.949 until the disc family's broadside cd went
# 0.2 -> 0.9, which is +3.7% on this hull -- the one reaction wheel it carries now bills
# 0.54 m2 of SideCdA (1.2 x cd x its 0.50 m2 broadside shadow) instead of 0.12. Nothing holds it -- the run is
# unguided -- so the hull leans west into the wind (pitch 90.00 -> 63.1 deg, 26.9 deg off
# vertical) and gains GROUND speed with it (hs 1e-2 -> 7.5 m/s), and hdg settles at
# 269.71-270.20 across four runs: due west, straight upwind of an east wind. That is why the
# pins below changed SHAPE rather than numbers. aoa closes on the nose axis far faster than the
# climb alone explains and then crosses it (the row the 6 s cutoff lands on reads +0.94 .. +1.38
# depending on which instant that is, where the lean has overtaken the flow's own ~25 deg), and
# the air-relative excess over the ground speed stops falling and turns back up. So the case
# pins the vector identity of the flight instead of bands read off the old windless one.
# #499 hung the SURFACE window's stability pair off the same line, and the racer
# is the case that shows the honest way to report an airframe with nothing lifting:
# cla prints 0.0 (the substep measured the air and found no slope), while sm DASHES.

# that cancelled had the drag log saying Np=+15.9 m, then +121.5, then -89.7 for

# #450: beta= is the yaw-plane half of the same AeroFrame pair. Until it was
# printed, the sideslip that keys the hull-silhouette cache (#463) had no instrument at all --
# the [drag] line printed it, [surfinfo] did not, so the two dumps of the same substep disagreed
# about what was measured. Same dash rule as aoa= for the flow-MAGNITUDE half: no usable flow,
# no angle. The wind exposed the other half, which a speed floor cannot see at all -- a 5.8 m/s
# flow is comfortably "usable" yet lies in the hull's pitch plane, where the yaw angle is
# undefined. #787 fixed that: beta now dashes when the flow is within kBetaIllCondDeg (1 deg)
# of the hull's up axis, which is the parked half of this run.
# #498: aprg= is the third reader of the same flow -- the angle from the nose to the
# AIR-relative prograde, which is what the new yellow marker pair points at. It is
# dashed on the same test as aoa=/beta= because it needs the same thing: air, and a
# flow with a direction.
NAME surface-aoa-readout
CLAIM [surfinfo] reports the aero angle of attack, the sideslip and the air-relative prograde while the ship has air-relative flow and "-" when it has none -- and dashes the sideslip alone when the flow has a direction but no yaw to report, which is what a broadside wind at a nose-up hull is. On a windy pad the numbers it reports are the wind's own vector: broadside at rest, tas the ground speed with the air's motion added, and upwind once the tall hull turns into that wind. Its stability pair reports a zero slope without inventing a neutral-looking margin for an airframe that has nothing lifting.

# PARKED (t < 1.2 s): the hull's own speed is 1e-5 m/s and the air's is the file's. tas is
# |airRelativeVel|, wind_east is the authored table interpolated at alt_asl (Kerbin: 5 m/s at
# alt 0, 40 m/s at 11205 m, and the pad sits at 264 m), and at rest the two are the same number
# to the digit -- 5.82 both. That equality is the whole wind feature in one row: the aero law is
# billing air the file authored, not a stillness the file never claimed.
CHECK all(4.8 < s["tas"] < 6.2 for s in surf if s["t"] < 1.2)
CHECK all(abs(s["tas"] - s["wind_east"]) < 0.02 for s in surf if s["t"] < 1.2)
CHECK all(5.6 < s["wind_east"] < 6.0 for s in surf if s["t"] < 1.2)
# And it is the table's wind, not a constant bolted to the hull: over the 78 m this climb gains
# (264 m to 342 m) the column itself walks 5.82 -> 6.07, which is the 5-to-40 m/s ramp read at
# each row's own altitude. A pin spread over 6.0 m/s of altitude is a band; the column RISING
# with the hull is the part that cannot happen if the wind were one number or read off the deck.
CHECK all(5.6 < s["wind_east"] < 6.3 for s in surf)
CHECK all(s2["wind_east"] > s1["wind_east"] for s1, s2 in zip(surf[:-1], surf[1:]) if s2["alt_asl"] > s1["alt_asl"] + 1.0)
# A nose-up hull under a horizontal wind meets it broadside: aoa -90.00, aprg +90.00, on
# every parked row. Before the wind these rows dashed (jitter under the 0.1 m/s flow floor);
# the number that replaced the dash is the geometry the wind implies, so it is pinned to a tenth
# of a degree rather than re-banded.
CHECK all(abs(abs(s["aoa"]) - 90.0) < 0.1 for s in surf if s["t"] < 1.2)
CHECK all(abs(s["aprg"] - 90.0) < 0.1 for s in surf if s["t"] < 1.2)
# CLIMBING -- AND TURNING INTO THE WIND. Once the hull has any real horizontal speed (hs > 0.2,
# from t=3.4 on) its heading is 269.71-270.20 deg: due west, straight upwind of the
# +5.87..+6.07 m/s of east air. That is the weathervane, and it is what makes the vector below
# writable without trig -- in this regime the ground velocity is vs up plus hs west, the air is
# wind_east east, and beta ~ 0 keeps the flow inside the pitch plane, so
#     tas^2 = vs^2 + (hs + wind_east)^2
# Measured |tas^2 - pred| <= 4.4e-3 against a tolerance of 0.05: eleven times the spread, four
# orders below what the wind leg is worth ((hs + wind_east)^2 is 37-185 m2/s2 across these
# rows), and the printed columns are %.6g, so tas alone carries ~4e-5 m/s of rounding. Drop the
# wind out of that expression and the same expression misses by 37-126 -- a ground-speed tas is
# not this number by any reading. CHECK namespaces have no math module -- CHECK_BUILTINS is an
# allowlist of abs/len/min/max/float/int/zip/set/sum/sorted/tuple/range/re -- which is why the
# pin squares both sides instead of taking a sqrt with sin(hdg) in it. Squaring also says why
# the identity is only claimed past hs > 0.2: below that the "horizontal" is 1e-2 m/s of jitter
# pointing wherever, and hdg is not a heading (the parked rows read 4.1 and 344.9 in one run,
# 116.3 and 352.4 in another -- and the pin is not merely loose there, the column is meaningless).
# This replaces the old "tas - vs falls monotonically" pin. That was never a law, and the turn
# killed it: the excess bottoms out and climbs again because the hull's own 6.6-7.5 m/s of west
# speed ADDS to the crosswind it flies into. What is pinned instead is the identity plus the two
# facts that make it mean weathervaning: hdg upwind, and hs strictly growing through the burn.
# The band is 270 +- 1 rather than the +- 0.06 the first measurement suggested: four runs put the
# flying rows inside 269.71-270.20, and a heading anywhere off the wind is what reddens it.
# The row count is pinned first because three of the four CHECKs in this block filter on
# hs > 0.2, and an empty filter reads as a pass (#653) -- measured 5 or 6 flying rows per run.
CHECK len([r for r in surf if r["hs"] > 0.2]) >= 4
CHECK all(269.0 < s["hdg"] < 271.0 for s in surf if s["hs"] > 0.2)
CHECK all(s2["hs"] > s1["hs"] for s1, s2 in zip([r for r in surf if r["hs"] > 0.2][:-1], [r for r in surf if r["hs"] > 0.2][1:]))
CHECK all(abs(s["tas"] ** 2 - (s["vs"] ** 2 + (s["hs"] + s["wind_east"]) ** 2)) < 0.05 for s in surf if s["hs"] > 0.2)
# tas still always exceeds the ground's vertical speed while the hull climbs, and the excess
# stays inside what the identity allows for 5.8-6.1 m/s of crosswind plus up to 7.5 m/s of the
# hull's own. Rearranged out of the identity, excess = (hs + wind_east)^2 / (tas + vs), where
# the numerator leg is 34-185 m2/s2 and the denominator 9.2-60 m/s across these rows. So the
# excess is biggest on the FIRST row that clears vs > 2 -- there vs is only 2.4-2.8 m/s, the
# denominator barely covers the crosswind, and the excess reads 2.3-3.9. It then falls to ~1.12
# while the climb outruns the air, and climbs back to 3.0-3.9 as hs grows and the throttle-down
# row takes vs back down. Measured 1.12 min, 3.91 max; 4.5 leaves ~15% room, and all of it sits
# on a row whose position in the schedule moves (the first vs > 2 row landed at t=1.7, 1.9, 1.9
# and 2.3 in four runs).
CHECK all(s["tas"] > s["vs"] for s in surf if s["vs"] > 2.0)
CHECK all(0.5 < s["tas"] - s["vs"] < 4.5 for s in surf if s["vs"] > 2.0)
# aoa closes on the nose axis through the burn -- from -42.7 .. -64.8 deg on the first row whose
# climb clears 2 m/s (vs 2.4-6.2) to about -1 deg near the cutoff -- both because the climb
# outruns 6 m/s of crosswind and because the hull turns into it. The filter cuts on SIGN rather
# than on a stop time: the last row of the run has the lean overtaking the flow angle and aoa
# flipping positive (+0.94 .. +1.38), so |aoa| turns around there, and pinning the last row out

CHECK all(abs(s2["aoa"]) < abs(s1["aoa"]) for s1, s2 in zip([r for r in surf if r["t"] >= 1.9 and r["aoa"] < 0][:-1], [r for r in surf if r["t"] >= 1.9 and r["aoa"] < 0][1:]))
# Once the nose has leaned > 20 deg off vertical (pitch < 70 -- the last two rows) the flow sits
# within 5 deg of the axis: measured aoa -0.97 and +1.38 on the harness run. The pin here used to
# demand 8-12 deg at 4.9 < t < 5.6; that window is gone rather than retuned. In the windless
# flight those seconds WERE the top of the climb with aoa still 11 deg off; this flight passes 8
# deg near t=4.4 and is inside 1.5 by 5.4. Pitch is the phase-free way to name "top of the
# climb" -- it is the hull's own state, not which instant the wall-clock sampler happened to hit
# (#1054). Pinned as a fact first so the filter below cannot be quietly empty: the hull does lean.
CHECK min(s["pitch"] for s in surf) < 70.0
CHECK all(abs(s["aoa"]) < 5.0 for s in surf if s["pitch"] < 70.0)
# aprg and aoa are the same flow read twice -- the direction the air is going, and the angle it
# arrives at -- so their MAGNITUDES agree. They are NOT equal and opposite, which is what this
# case used to claim: aprg= is glm::angle(facing_dir, air_dir) and therefore unsigned
# (gameui.cpp), while aoa= is the signed lastDragAlpha the aero law measured. Every pre-wind
# row had a negative aoa, so the sum looked right by accident; the first row whose flow crosses
# the nose axis (t=5.9, aoa +1.38, aprg +1.40) breaks the SUM by 2.77 while the magnitudes agree
# to 0.018. Measured |aprg| - |aoa| = -0.45 .. +0.02 over twelve rows and four runs; the widest
# is the first climbing row, where aoa moves ~50 deg/s (it walks -90.00 -> -64.79 in one 0.5 s
# row), so 0.45 deg is about 9 ms between the view's snapshot and the drag substep that fills
# lastDragAlpha -- two readers of one flow, not two numbers. #1208 re-measured it: the disc
# family's broadside cd went 0.2 -> 0.9, the wind grabs this stack harder, and that worst row
# now reads 0.455 .. 0.511 over NINE runs, so the old 0.5 deg window sat INSIDE the run-to-run
# spread (0.056 deg) instead of above it -- this case was a coin flip that #1208 happened to
# land on. Window is 0.75 deg: ~1.5x the worst measured row, still ~30x under the
# tens-of-degrees gap that either reader reading the ground instead of the air would show.
# It stays a sampling-skew pin, not a value pin.
CHECK all(abs(abs(s["aprg"]) - abs(s["aoa"])) < 0.75 for s in surf)
