# A ring of bells turns a hull with no wheels and no armed engine (#595), and #677 proved
# the kill-rot law asks it to. What #679 found is that the law keeps asking after the hull
# has STOPPED, and the tank keeps falling: hold kill-rot on rcs_test, watch |w| reach
# 0.0000 at t=6.7, and --drain-log prints 0.026-0.098 kg/s for the next two and a half
# seconds while the key stays down. The [mass] rows say the tank fell 0.18-0.32 kg over
# such a run -- bimodal, because a wall-clock key release lands differently between runs
# (#1054) -- against 0.06-0.07 kg once the noise rows are gone. Call it 5 kg a minute of
# propellant to hold a still ship.
#
# The culprit is not the law and not the ring's rating. It is a row with a HAIR of
# authority. Vehicle hands the torque solver one row per bell, priced cross(arm,dir) x
# thrust, and the solver (actuators.h) fits a demanded vector with no notion of what a row
# COSTS. Each rcs_box authors five bells, and one of them points radially out from the tank
# wall, so its axis passes through the COM: its lever is roundoff -- 1e-15 N m at spawn,
# up to ~2e-9 in flight, against the 69 N m the ring's other sixteen bells lever. The residual ask of 0.0002 N m is
# enormous next to that. The solver loads the bell to its LIMIT -- the descent is happy with
# any split along a shared direction, so it gives the weak line its whole capacity and the
# strong bells the rest -- and applyRcsForce then bills gas by THRUST, not by torque, so
# four 60 N bells went off for 1e-9 N m. Measured with a temporary probe: ask 0.0002 N m,
# four bells at s=1.0, 120-240 N of gas every other substep, |w| = 0.0000 the whole time.
#
# The fix is in row building, not in the solve: a bell under 0.1% of its own ring's best
# lever is not a steering actuator at all. It stays fully creditable to rcsPlan for PUSHING
# -- that is what a bell through the COM has always been good for -- it just cannot be spent
# on pointing. The margin is not close for any built hull: the shipped bells sit 10 orders
# either side of the cut. tests/test_authority.cpp pins the cut and the saturated-bell
# arithmetic in a fixture; this case is the same fact flying, off --drain-log rather than
# the [fuel] print, whose one decimal cannot see a 0.1 kg burn.
#
# The stop itself still pays: 0.056 kg/s while 138 N m is putting 0.88 rad/s down. Post-fix
# rows for these ARGS print 0.056, 0.022, then 0.000 from t=7.5 on.
NAME holding-a-stopped-ring-hull-does-not-drink
CLAIM Holding kill-rot on a ring-steered hull that has already stopped drinks nothing, while the stop that got it there still costs.
KIND invariant
ARGS --time-accel 1 --startship rcs_test,res/ships/rcs_test.json,Kerbin,inertial-orbit
ARGS --slew-log --drain-log --no-paint
ARGS --sim-press 3000,600,S,6000,3000,X
ARGS --timeout 12
LIMIT 40
EXPECT [drainlog]
FORBID error:
FORBID FAILED
# S (pitch) for 600 ms at 3.0 s is the disturbance; X (kill-rot) is HELD from 6.0 to 9.0 s,
# which is what the player does -- X is an override, not a latch. Same bed as
# flight/677-kill-rot-stops-a-ring-only-hull, so the two cases read the same fixture.
CHECK len(slew) >= 15
CHECK len(drainlog) >= 15
# THE HULL DID STOP, and stayed stopped while the key was still down. Without this the
# drain pins below could pass by the ring going dead, which is #677's bug wearing the
# opposite face.
CHECK max(s["wnorm"] for s in slew) > 0.25
CHECK min(s["wnorm"] for s in slew) < 0.01
CHECK all(s["wnorm"] < 0.02 for s in slew if s["t"] > 8.0)
# THE RING WAS WORKING DURING THE STOP: tau_spent sits on the 138 N m pitch rating, and
# the ring drank while it did. rcs_test is priced at 276/138/138 N m (R/P/Y) by
# --steering-log; the ring's leverage is unchanged by the fix, and this is where the
# fix must NOT show up.
CHECK max(s["tau_spent"] for s in slew) > 120
CHECK max(r["rates"][0] for r in drainlog if r["t"] < 7.0) > 0.03
# THE HOLD COSTS NOTHING. The stop is done by t=6.7, so the first row that cannot still be
# carrying the stop's spend is t >= 7.4. Before the fix these rows read 0.026-0.098 kg/s
# steady; post-fix they print 0.000.
CHECK all(r["rates"][0] < 0.005 for r in drainlog if r["t"] >= 7.4)
# AND THE RUN AS A WHOLE. What is integrated here is NOT kilograms: a row's g0= divides by
# the seconds that group actually FLOWED (drainSpentSpan_), while dt= is the whole print
# window, so rate x dt is an upper bound on the row's spend, not the spend -- 0.093-0.096
# summed against the 0.06-0.07 kg the [mass] rows say this run really lost. It is still the
# right instrument for this claim because the same over-count sits on both sides of the
# comparison: these ARGS sum 0.093-0.096 with the guard and 0.23-0.41 with it off. The
# floor is the tap's 0.6 s and the stop's 0.7 s of 138 N m, which are real spending; the
# ceiling is what would catch a hull that went back to burning through a hold. If #1143
# ever prints the window's spend instead of this rate, all four fuel pins here and in
# 595/677/1067-c want re-reading against the real kilograms.
CHECK sum(r["rates"][0] * r["dt"] for r in drainlog) > 0.03
CHECK sum(r["rates"][0] * r["dt"] for r in drainlog) < 0.15
