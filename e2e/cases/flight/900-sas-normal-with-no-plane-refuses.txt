# SAS Normal on a vertical climb: the state has a velocity, a radius and no PLANE.
#
# #891 put #870's speed floor in front of Vehicle::slewTargetDir() and closed the prograde
# half. The normal pair (SlewNormal / SlewAntiNormal) reads the same function but answers a
# different question, and a speed floor does not answer it: the normal is cross(pos, vel),
# magnitude h = r |v| sin(gamma). A near-radial state has a LARGE |v| and a vanishing
# sin(gamma), so it clears the speed floor many times over while the whole angular momentum
# of the "plane" is the residue of the last sideways cm/s. Measured on this bed before the
# fix (tmp/night3/891r_normal_pad_liftoff.log): of 27 consecutive `target=` pairs, 10 jumped
# by more than 90 deg, the worst 174.0 deg between t=3.100 and t=3.217, while `[orbinfo]`
# called the conic radial (ecc=1, peri_r 3e-4 m at r 599681 m) and never slow. SAS spent up
# to 4.04e6 N m of drum ask turning the nose toward a heading that reversed between frames.
#
# The floor is orbit.h's kConicNormalFloor on h/r -- the TANGENTIAL speed, m/s at any
# scale -- refused below 0.1 m/s. Both ends measured: the pad's residue sits at 6.8e-4 m/s
# and the climb runs 1.4e-2 .. 7.6e-2, while the slowest tangential speed a conic BOUND to
# any shipped body reaches (surface periapsis, that body's own sphere of influence as the
# apoapsis) is 1.48 m/s on Eeloo -- the tightest in ksp_system, with Kerbin at 24.4 m/s.
# Reusing kConicSpeedFloor (1e-2) unchanged would NOT have refused the climbing rows. Below
# the floor the target is the zero vector, which is the ask pointingTo() already fails
# closed on (#609), so the row prints `no-target`.
#
# What is pinned here is that SAS and the DRAWN normal now refuse together: render.cpp used
# `dot(h_hat, h_hat) > 0.5` and the ascent row `ang_momentum > 0.0`, and orbit.h makes h_hat
# exactly unit or exactly zero, so both were tests for exactly zero -- which is nowhere the
# noise starts. [planelog]'s nrm= dashes through the near-vertical phase, on the same
# timeline the bill prints no-target.
#
# What stays on the far side of the floor, and the honest reason it stays. From ~4.5 s the rows
# resolve, and it is NOT "the player steered into a plane of their own": no steering key is
# pressed here (R is throttle, T is thrust), and the resolved rows show SAS itself slewing --
# w_slew 0.02 .. 1.07 rad/s while the nose walks off vertical and E falls 89.3 -> 65.2 deg. The
# law turns the hull, the hull earns tangential velocity (0.1 .. 1.2 m/s when this was written;
# 5-6 m/s more today, most of it the air's -- see THE AIR GIVES THE CLIMB A PLANE below), h/r
# clears the floor, and the plane is a consequence of steering the floor refused earlier. By then
# the state really does have a plane, so this is not the bug; but the mode also flaps across the
# floor on the way (measured on the current build: resolved 4.500 and 4.600, refused 4.700,
# resolved from 4.817 -- three transitions in 0.3 s on a mode the player latched), and an ask
# parked near E = 90 deg is a max-rate turn about an axis the noise picks. Both of those are
# filed as follow-ups rather than pinned here. #900 changed the refusal and the marker's
# agreement with it, and that is what these CHECKs hold.
#
# THE AIR GIVES THE CLIMB A PLANE (#1132 family D, re-measured 2026_11_23). The bands quoted
# above stop holding at the end of the run, and the reason is the same authored air that turned
# 395's racer: Kerbin's 5-6 m/s of east air pushes a nose-up hull sideways, sideways velocity IS
# angular momentum, and peri_r = h^2 / (mu (1 + ecc)) reads it out. A/B, same schedule, same
# hull, same fixture with its wind table deleted (tmp/night7/900-no-wind.json), three winded
# runs and one windless run on the current build:
#     with wind    peri_r 6.8e-10 -> 0.82-1.58 m, ecc 1 -> 0.999995-0.999997, refused
#                  38 / 39 / 38 of 52 rows, marker dashed 1 of 3 rows in all three
#     windless     peri_r 5.6e-9 -> 2.07e-6 m, ecc 1 throughout, refused 53 of 53,
#                  marker dashed 3 of 3
# Nine orders of peri_r inside a winded run against three without, and the last row is 0.82-1.58
# m rather than 2.1e-6 m. So "genuinely near-radial" is a statement about the first five seconds,
# not the whole run, and the pin that demanded peri_r < 1 m on EVERY row was really demanding
# that the wind not blow. What the case holds is the refused window plus the arrival of the plane
# the wind made; the windless half is reproducible with that fixture copy but stays out of the
# battery, because a second case on the same premise costs a run and #900's law is already
# pinned by tests/test_orbit.cpp numerically.
# #905 (open) tracks the flapping and this wind-driven resolution; the A/B above is on it as of
# 2026_11_23.
#
# One bound on what the marker CHECKs can cover: [planelog] is printed from inside
# drawOrbitPlane(), which returns early for a grounded hull, so this run's rows start at
# ~3.4 s (liftoff), not at t = 0. The pad's residue window is therefore pinned by the BILL,
# which runs at 10 Hz from t = 0.017, and not by the marker.
# The pad is authored, not shipped: e2e/fixtures/systems/870-kerbin-polar-pad.json is the
# shipped Kerbin verbatim (air, mass, rotation, seed) with one pad at lat 90. The shipped
# polar_pad used to be that pad; #1007 moved it 12.6 km (1.2 deg) off the pole to the
# nearest dry flat ground, and a launch from there starts with ~3.6 m/s of sideways ground
# motion instead of none -- which is a different climb from the one whose bands are quoted
# above. Same body and same air here, so those bands carry over.
NAME sas-normal-with-no-plane-refuses
CLAIM SAS normal on a near-radial Kerbin climb refuses instead of steering at a plane made of residue, and the drawn normal dashes on the same rows -- until the authored wind hands the climb sideways velocity of its own and the plane stops being residue.
KIND invariant
ARGS --system e2e/fixtures/systems/870-kerbin-polar-pad.json
ARGS --startship racer,res/ships/racer.json,Kerbin,pad,polar_pad
ARGS --time-accel 1 --timeout 6 --autopilot normal --slew-log --plane-log --info-log --orbit-interval 1
ARGS --sim-press 1000,2000,R --sim-press 3000,3000,T
LIMIT 200
EXPECT [slew]
EXPECT [planelog]
EXPECT mode=normal no-target
EXPECT nrm=-
FORBID error:
# The premise, pinned from the readout rather than assumed. This is NOT #891's state: the
# hull is genuinely moving (21.2-21.9 m/s by the cutoff), and it is genuinely near-radial for
# the refused part of the run -- peri_r = h^2 / (mu (1 + ecc)), so a periapsis 1.4-1.7 mm from
# the focus at r ~599,700 m while the hull climbs at 14.5 m/s says h itself is microscopic.
# That is what makes "no plane" the honest answer rather than "slow". The window is cut by
# velocity rather than by time because the refusal ends when h does, not at a wall-clock
# instant: rows under 16 m/s run peri 6.8e-10 .. 1.7e-3 m across three runs, and the 21-22 m/s
# row that follows is 0.82-1.58 m.
CHECK len(orbinfo) >= 3
CHECK any(o["vel"] > 10.0 for o in orbinfo)
CHECK all(o["peri_r"] < 1.0 for o in orbinfo if o["vel"] < 16.0)
CHECK all(o["r"] > 5.9e5 and o["r"] < 6.1e5 for o in orbinfo)
# And the plane really does arrive, which is the other half of why the pin above is a window:
# against the pad's own residue (the parked rows, vel < 0.01 m/s) the last row is orders of
# magnitude less radial. Measured last-row peri 0.82 / 1.56 / 1.58 m against parked peri
# 1.65e-7 / 2.98e-7 / 9.47e-7 m, so the ratio is 1664 .. 5.2e6 depending on which way the pad's
# jitter went, and ecc 1 -> 0.999995-0.999997. A windless Kerbin keeps that ratio under 5
# (2.07e-6 against 4.59e-7), so 100x is the pin: sixteen times clear of the worst measured run
# and twenty times clear of the windless one. The ratio pin is itself a wind witness.
CHECK last(orbinfo)["peri_r"] > 100.0 * max(o["peri_r"] for o in orbinfo if o["vel"] < 0.01)
# Refusal for most of the latched run, not one lucky tick: [slew] runs at 10 Hz over 6 s of
# autopilot, and the mode is latched the whole time (the EXPECT on the mode name keeps an
# unlatched run from reading as a vacuous pass). The margin is not laziness: --sim-press is
# WALL-clock timed (#138, #871), so the keys land a step or two apart between runs and the
# launch geometry differs -- measured on one build, three runs: 52 [slew] rows, refused
# 38 / 39 / 38 of them. Any CHECK here that pins a count to 1 is a flaky case, and the state
# sits right ON the floor around 4.5-4.7 s, which is where the accepted rows flicker.
CHECK out.count("mode=normal no-target") >= 30
# The other direction, and the one that was missing: a floor set absurdly HIGH (1e3 m/s,
# say) passes every other CHECK here -- every row refuses, len(slew) is 0 so all() is
# vacuously true, and every nrm is dashed. Three rows is the keep end in that direction;
# the numeric bracket itself (~1.48 m/s on Eeloo, the tightest shipped body) lives in
# tests/test_orbit.cpp, where both ends are pinned as numbers rather than as a scenario.
CHECK len(slew) >= 3
# And the accepted minority stays small, which is the half a mutation would blow up: delete
# the conicNormal() guard and every row resolves -- out.count drops to ~6 and len(slew)
# climbs to ~53, with the target reversing frame to frame.
CHECK len(slew) <= 20
CHECK all(s["mode"] == "normal" for s in slew)
# The marker and the autopilot cannot claim different planes: render.cpp and slewTargetDir()
# ask the same conicNormalOk, so [planelog] dashes the normal for the same states the bill
# refuses. Held on the FIRST marker row -- the one at liftoff, which is the same state the bill
# has been refusing since t=0.017 -- and on the existence of a dashed row. Measured three runs:
# 1 dashed of 3 in every one, the dashed row being t=3.5, because the resolve lands at 4.5-4.7 s
# and the marker cadence is 1 s from liftoff. The old ratio pin (drawn * 2 <= rows) therefore
# reddened on sampling phase alone -- an earlier pair of runs gave 2 dashed of 3 -- which is not
# a law and not what #900 fixed; the flapping is already filed above as a follow-up. Take
# conicNormalOk out of render.cpp and every row draws one (the old `dot(h_hat, h_hat) > 0.5` is
# an exactly-zero test, and h_hat is never zero here), which reddens the EXPECT above, this row
# and the dashed-count pin together. And the LAST row draws one in 3 of 3 winded runs while the
# windless fixture keeps all three dashed, so a renderer that dashed everything would not pass
# either: the drawn normal is the air's plane arriving.
CHECK len(plane) >= 2
CHECK sum(1 for p in plane if p["nrm"] is None) >= 1
CHECK plane[0]["nrm"] is None
CHECK plane[-1]["nrm"] is not None
