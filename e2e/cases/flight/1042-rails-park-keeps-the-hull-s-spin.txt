# Parking a hull on rails and waking it is supposed to be a no-op for its MOTION. The
# conic keeps rail_pos and rail_vel, and the frame hop converts the stasis terms through
# switchFrameState (#946's discipline). The angular half had no rail field at all:
# writeRailPose() ended with SetAngVelocity(hull, 0), so every rails excursion dropped the
# hull's spin (#1042). The rails state is vehicle.h's rail_pos/rail_vel/rail_orient -- no
# angular member -- and railAdvance() asserts frame->omega_total == 0, so a coasting conic
# lives in the inertial node and a spin can only come back if it was stored there.
#
# The instrument is the Docking dial's twist= (#1026, #1041): |w_a - w_b|, the RELATIVE
# spin of the pair, which is the figure a pilot docking actually has to kill. gameui.cpp
# says outright that it is NOT the flight panel's "Angular rate", because that one is read
# against the hull's own frame and jumps when F6 parks a hull and wakes it again -- which
# is exactly the bug, wearing a disguise: a row that changes when nobody touched anything.
#
# --dock-test spin is an 8 m aligned pair -- too far to ever mate, so the run keeps both
# hulls selectable -- with the probe rolling 4 deg/s about its own bore. A roll about the
# bore is the one spin that changes nothing else about the pair: the cone and both distance
# gates read the same figures as at rest, so the dial's twist= is the whole subject. The
# fixture used to supply spin by accident: its authored velocity was a few cm/s off, which
# drove the two port meshes through each other and let the contact torques tumble the pair
# (that is where the old 3.7 deg/s came from, and why this case read a drifting, wandering
# rig). #1152 cleaned that velocity up, so a case that wants spin now asks for it.
NAME rails-park-keeps-the-hull-s-spin
CLAIM Parking a hull on rails and waking it keeps the spin it had: the docking dial's relative twist is the same figure on both sides of an F6 round trip, and not zero.
KIND invariant
ARGS --dock-test spin --time-accel 1 --timeout 6 --width 1280 --height 720
ARGS --ui-click 1500,"Windows/Docking"
ARGS --sim-press 3000,0,F6,4500,0,F6
EXPECT Dock-test (spin): the probe rolls at 4 deg/s about its own bore
FORBID FAILED
# The window has to have been open across the whole sequence, and the two handoffs have
# to have happened: without them this is a run where nothing was parked and every CHECK
# below is weighing a pair that never moved.
CHECK len(dockwin) >= 6
CHECK len([s for s in shipswitch if s["verb"] == "switch"]) == 2
CHECK all(r["twist"] is not None for r in (first(dockwin), last(dockwin)))
# Both ends are spinning pairs, so the equality below cannot be satisfied by a dead rig.
# The authored roll is 4 deg/s and the dial reads 4.00 on every measurable row, so the
# band is the figure itself rather than "some spin": at > 1.0 a rig that had lost most of
# its spin -- which is exactly what the rails used to do -- would still clear the floor.
CHECK 3.9 < first(dockwin)["twist"] < 4.1
CHECK 3.9 < last(dockwin)["twist"] < 4.1
# The round trip. Measured across the two runs of this case: with the old zeroing the dial
# reads twist=4.00 before the F6 pair and 0.00 after it -- one hull's spin against the
# other's stationary one. With rail_omega carried, the same schedule prints 4.00 through
# all nine measurable rows, so the band below is only allowing what the rails round trip
# could not itself change, while the defect misses it by the whole 4.
CHECK abs(last(dockwin)["twist"] - first(dockwin)["twist"]) < 0.3
