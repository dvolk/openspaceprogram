# #498: inside an atmosphere on a rotating body the air co-rotates with the ground,
# so the CONIC's velocity -- which is what the green prograde marker, the orbital-plane
# overlay and [orbinfo]'s prg= have always read -- is mostly the GROUND's own
# motion. Kerbin carries the sea-level ground ~175 m/s, so an airframe whose conic speed
# is 185-235 m/s while it is doing 30-96 m/s through the air has its conic prograde
# 21-52 deg off the nose while the aero law says the nose is ON the flow. Measured on
# this build (skiff_trim, flying-cruise, --info-log, --orbit-interval 2, --sim-steps
# 960; aprg= is the
# air-relative key -- the same number the Game Debug window's Prg (air) row prints -- and
# prg= the conic one (that pair's Orbital-window row went away on 2026_11_06, so this log
# is where it lives):
#
#   t= 2.0  aprg   4.90  aoa   4.90  beta -0.006   prg  30.54  vel 245.9 m/s
#   t= 4.0  aprg   4.95  aoa   4.95  beta -0.007   prg  31.58  vel 241.4
#   t= 6.0  aprg   5.03  aoa   5.03  beta -0.006   prg  31.32  vel 238.0
#   t= 8.0  aprg   5.05  aoa   5.05  beta -0.001   prg  30.75  vel 236.4
#   t=10.0  aprg   4.99  aoa   4.99  beta  0.001   prg  31.11  vel 236.6
#   t=12.0  aprg   4.92  aoa   4.92  beta  0.002   prg  31.67  vel 238.4
#   t=14.0  aprg   4.87  aoa   4.87  beta -0.001   prg  31.38  vel 241.2
#   t=16.0  aprg   4.85  aoa   4.85  beta -0.002   prg  30.47  vel 243.9
#
# Before #686 the same case read aprg 4.98-5.30 against prg 19.1-28.2. The bed moved from
# 7.0 to 8.5 km and Kerbin's air became 1.44x denser there, so the bed's 80 m/s spawn was
# 1.9x this hull's trimmed glide instead of 1.6x and its first exchange was much deeper:
# aprg 4.7..12.0 against prg 21..52, converging to 9.3 deg at the top of the climb, where
# the conic still read 185.6 m/s while the air-relative flow had fallen toward the glide.
# Kerbin carrying air flattened all of that. The bed's 80 m/s is a GROUND speed and the
# column is worth 31.6 m/s at that band, mostly under the hull, so it arrives with ~48 m/s
# of air -- near its own glide -- and there is no deep exchange to climb out of. aprg holds
# 4.85..5.05, prg holds 30.5..31.7, and the gap is 25.6..26.8 deg on every row instead of
# 9.3..47.3. What is left is the half that was never about the arc: the conic reads the
# ground's 175 m/s of co-rotation, the air-relative readout reads the plane's 48 m/s, and
# the two disagree by a quarter-turn no matter how steadily the hull flies.
# That is the honest shape of the complaint.
#
# The window is gated in LOGIC TICKS, not wall clock. With --timeout 16 the eight rows
# landed at t=1.8, 3.9, ... 15.9 and their phase moved run to run: the same ARGS gave
# aprg max 12.43 and 12.52 and a gap floor 9.43 and 9.63 deg on two runs of the same
# binary, which on a 9.0 deg floor is 0.4 deg of luck. --sim-steps 960 is 16 s of game
# time at --time-accel 1, and every run since prints the table above to the digit.
#
# Both readings are correct about what they measure; the issue was that only one of
# them existed for a pilot. The air-relative direction (view.air_dir, built from the
# same Vehicle::airRelativeVel the drag law uses) now has its own yellow marker pair
# and this key. The conic pair stays where it was -- #204/#205 pin it in the orbital
# plane, and moving it would break them.
#
# What is pinned, in order: both windows printed; the air-relative angle exists all
# the way through an in-atmosphere run; it AGREES with the angle the aero law
# measures (with Beta at zero, nose-to-air IS AoA -- one vector, two consumers, so
# they cannot disagree); and the two progrades never collapse into one another, the
# conic one drifting, which is the whole complaint. The markers themselves are only on
# screen: e2e cannot read imgui rows or billboards (#333), so the numbers are the pin.
NAME surface-prograde
CLAIM A plane cruising inside an atmosphere reads two different progrades: the air-relative one sits 4.85-5.05 deg off the nose -- the same angle the aero law calls its angle of attack -- while the conic one sits 30.5-31.7 deg off, because the conic points where the ground is going rather than where the plane is flying.
KIND invariant
ARGS --time-accel 1 --sim-steps 960 --startship skiff_trim,res/ships/skiff_trim.json,Kerbin,flying-cruise
ARGS --info-log --orbit-interval 2
EXPECT [orbinfo]
FORBID error:
CHECK len(surf) >= 6
CHECK len(orbinfo) >= 6
# Air the whole run, and the flow never falls under kAoAFlowFloor even at the top of the
# climb, so the air-relative direction is never dashed. (The dash rule -- no air, or a
# flow slower than kAoAFlowFloor -- is pinned in flight/395, where the ship starts
# parked.) The 4-12 deg here rather than the 2.4 this table used to quote is #568: the
# pod-on-tank stack holds a higher angle of attack at the same 12 deg of elevator. The
# top of the range is #686's deeper exchange, not a new reading of the marker.
CHECK all(s["aprg"] is not None for s in surf)
CHECK all(abs(s["aprg"]) < 13.0 for s in surf)
# The band is not all slack: the hull holds a real 4.85..5.05 deg of angle of attack on
# the air it is flying through, and a marker wired to the conic vector would read 30.5
# here instead. (It used to reach 12.0 at the top of a deep exchange; Kerbin's column took
# 32 m/s off this bed's spawn air, so the exchange never got deep -- see the table above.)
CHECK max(s["aprg"] for s in surf) > 4.5
# The split between the two progrades is a pose property (co-rotation x speed),
# not a plumbing one; it was pinned in the UI here and moved with every airframe.
# Dropped.
# One vector, two consumers: the nose's angle to the air and the aero law's own
# alpha must be the same reading. They differ only by sideslip, and Beta is next.
# Note the conventions: aprg= is a CONE angle (nose to air-prograde, 0..180, never
# signed) while aoa= is the signed pitch-plane angle the law uses. Nose-up they agree;
# nose-down they would differ by twice the angle. So compare against |aoa| and pin the
# sign this bed flies at, rather than letting the subtraction happen to work.
CHECK all(s["aoa"] > 0.0 for s in surf if s["aoa"] is not None)
CHECK all(abs(s["aprg"] - abs(s["aoa"])) < 0.5 for s in surf if s["aoa"] is not None)
# The skiff now carries ailerons, so a stick input leaves a little sideslip; the
# invariant is "small", not "zero".
CHECK all(abs(s["beta"]) < 3.0 for s in surf if s.get("beta") is not None)
# The conic prograde: far off the nose the whole run. Unwinded it also WALKED with the arc
# -- 21.28 deg at the top of the climb (t=10.0 s) against 52.27 at t=6.0 -- because that
# arc had a vertical leg to swing the ground-relative vector through. With the column
# flattening the arc, the walk is gone: 30.47..31.67 over the eight rows. Both ends are
# still pinned, and the ceiling matters more than it did -- it is what stops "prg is far
# off the nose" passing on a marker that merely wobbles.
CHECK all(25.0 < o["prg"] < 40.0 for o in orbinfo)
# The gap itself -- the smallest conic error in the run leaves 25.6 deg between the two
# instruments for the same ship in the same frame (measured 25.61 at t=2.0 s, 26.75 at
# t=12.0 s). It was 9.26..47.25 unwinded, and the floor went UP because the shallow run has
# no top-of-climb row where the two nearly agree: what is being measured now is the
# co-rotation term alone -- the ground's 175 m/s under a 240 m/s conic -- rather than that
# term occasionally cancelled by a vertical leg. Read the band again whenever the bed's air
# changes. Keyed on t= so an orbinfo row with no surfinfo twin raises instead of quietly
# comparing against the wrong frame.
CHECK all(o["prg"] - {s["t"]: s["aprg"] for s in surf}[o["t"]] > 20.0 for o in orbinfo)
