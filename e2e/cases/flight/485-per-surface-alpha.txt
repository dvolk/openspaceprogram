NAME skiff-per-surface-alpha
CLAIM The [surface] row #485 adds quotes all ten lifting or steering parts of the skiff on every --drag-log sample -- each one's own angle of attack signed into SHIP axes plus the dynamic pressure of the flow standing at it -- so a mirrored twin pair reads alike (wing_l and wing_r within 0.3 deg while the airframe is in the flow), the tailplane's -5 deg mount incidence shows as a 4.5-5.5 deg gap between tail and wing, the fin's angle IS the sideslip it is weathervaning against (within 1.2 deg of -Beta on rows over 4 deg), and each part's q matches 0.5*rho*v^2 inside 8%.
KIND golden
ARGS --time-accel 1 --startship skiff,res/ships/skiff.json,Kerbin,flying-cruise
# --no-paint: every assertion here parses [drag]/[surface] rows, so the 3D pass
# buys nothing and costs 95% of the frame (#666).
ARGS --sim-steps 3000 --drag-log --no-paint
ARGS --sim-press 500,3000,R,500,20000,T,25000,1000,A
EXPECT [surface]
# One [surface] line per [drag] line, and every line carries all ten surfaces: the
# aero pass finds a usable frame for each of them at this attitude, so the line length
# is fixed. That is also what lets the checks below read the parts by stride --
# wing_l, wing_r, tail_l, tail_r, fin, elev_l, elev_r, rudder, ail_l, ail_r, in the
# shipdef's part order -- instead of re-matching names. (Ten, not the eight this was
# written against: the aileron pair #563/#566 hung on the wing trailing edges is a
# steering surface too, so it prints.)
CHECK len(drag) >= 40
CHECK len(surface) == 10 * len(drag)
CHECK set(s["name"] for s in surface) == {"wing_l","wing_r","tail_l","tail_r","fin","elev_l","elev_r","rudder","ail_l","ail_r"}
# ... and in that ORDER, position by position. Every check below reads its parts by
# stride, so a reordering in shipdef or in the aero pass would otherwise pair a wing
# with a rudder and still print plausible angles.
CHECK all(s["name"] == n for s, n in zip(surface, (["wing_l","wing_r","tail_l","tail_r","fin","elev_l","elev_r","rudder","ail_l","ail_r"] * len(drag))))
# THE TWIN PROBLEM #485 EXISTS FOR. partAero measures alpha in each mount's own frame,
# and wing_l/wing_r (like tail_l/tail_r) are the same plate mounted at attach angle 0
# and 180, so their RAW alphas are equal and opposite while their forces are identical
# (#453). Printed raw, a healthy pair looks broken and a broken pair looks healthy.
# Signed into ship axes the pair agrees: on this run the wings agree to 0.1 deg and the
# tailplanes to 0.1 on every row the ship is not sideslipping (|Beta| < 0.6); the bands
# are 0.3.
CHECK max(abs(a-b) for a,b,g in zip([s["a"] for s in surface][0::10],[s["a"] for s in surface][1::10],[d["beta"] for d in drag]) if abs(g) < 0.6) < 0.3
CHECK max(abs(a-b) for a,b,g in zip([s["a"] for s in surface][2::10],[s["a"] for s in surface][3::10],[d["beta"] for d in drag]) if abs(g) < 0.6) < 0.3
# The ailerons are the same plate mounted the same mirrored way, one on each wing
# (#566), so they have to pass the twin test too -- measured worst 0.2 deg, on the
# quiet rows; the 0.3 band is 0.1 away, so re-measure rather than widen it.
CHECK max(abs(a-b) for a,b,g in zip([s["a"] for s in surface][8::10],[s["a"] for s in surface][9::10],[d["beta"] for d in drag]) if abs(g) < 0.6) < 0.3
# WHAT THE READOUT IS FOR: the angles the forces actually come from. The tailplane is
# bolted at -5 deg (shipdef "roll" on its mounts) and the elevators at 0, so a quiet
# run must show the tail ABOUT 5 deg BELOW the wing and the elevators on the wing's
# number -- which is #490's trim read part by part instead of one ship-wide AoA.
# Measured 4.9..5.7 on the quiet rows now, against 4.5..5.5 before the air started
# moving (#688). The widening is not the mount drifting: a part's local flow carries the
# rigid-body sweep term omega x r (#483), which is an ANGLE, so the same metre per second
# at the tail is atan(1/30) rather than atan(1/78) -- this run's AIR-relATIVE speed is
# 30.0..78.3 m/s while its inertial |v| runs 59.3..104.5. Same law, lower airspeed, wider
# noise around a mount that is still exactly 5.0.
CHECK all(4.5 < w - t < 6.0 for w,t,g in zip([s["a"] for s in surface][0::10],[s["a"] for s in surface][2::10],[d["beta"] for d in drag]) if abs(g) < 0.6)
# The elevators ride 1.2 deg UNDER the wing's number at the worst row of this run and no
# row puts them above it by more than 0.1. That gap is not the
# mount -- a tab bolted flat to its parent meets the flow at the parent's own angle,
# which is what the aileron bands below pin -- it is the flow arriving at the tail
# already angled down by the wing behind which it sits. The downwash angle tracks the
# wing's lift COEFFICIENT, and #686 left that near where it was: the same ~2.5 deg of
# AoA at the fast end, where this run's drag log bills 8.69 kN of |L| at 79.8 m/s in
# 0.50 kg/m3 (the same hull in the pre-#686 7 km air reached its fast end near 78 m/s in
# 0.35 kg/m3, i.e. near 5.7 kN) against a 5.6 kN weight. What moved is the arc's depth:
# the bed spawns at 1.9x this hull's trim rather than 1.6x (#693), so the run visits a
# wider AoA range and a deeper worst row than the old one did.
# The old -0.5 floor sat exactly on the old worst row, so the floor moves with the arc
# rather than the mount: -1.2 measured, at t=26 s in the middle of the rudder kick
# (the sweep term again, at this run's airspeeds), with 0.3 deg of slack.
CHECK all(-1.5 < e - w < 0.4 for e,w in zip([s["a"] for s in surface][5::10],[s["a"] for s in surface][0::10]))
# A tab bolted flat to a wing meets the flow at the wing's own angle: the ailerons
# hang off the wing's trailing edge (point/normal, #566, sat clear of it by #570). Each
# one is compared with the wing it is bolted through, NOT across the hull: sideslip
# makes wing_l and wing_r disagree (0.3 deg over this run, all of it on the kick rows),
# and ail_r against wing_l would sample that instead of the mount. Measured all the way
# through the run, rudder kick included: both tabs sit -0.5..+0.1 deg off the wing they
# hang on (0.5, not the old 0.3, for the same reason as the elevator band: the sweep
# angle at a wing tip grows as the airspeed falls) -- and #567's reshaped wing did not
# disturb that either: the tab still meets the air at its parent's angle.
CHECK all(-0.7 < x - w < 0.4 for x,w in zip([s["a"] for s in surface][8::10],[s["a"] for s in surface][0::10]))
CHECK all(-0.7 < x - w < 0.4 for x,w in zip([s["a"] for s in surface][9::10],[s["a"] for s in surface][1::10]))
# THE WEATHERVANE, MECHANISM AND NOT JUST OUTCOME. One 1 s rudder press at 25 s, never
# held. The ship yaws away and the fin meets the flow at exactly the angle it is
# weathervaning through, of the OPPOSITE sign: Beta -6.0 (t=27 s) -> fin +5.8, Beta
# +3.6 (t=29 s) -> fin -3.7. (Before #686 the same press read -7.7 -> +8.0 and +6.7 ->
# -6.8: the kick now lands further down the phugoid, where the hull is slower and the
# 1 s of rudder swings less air around it.) The rudder, which nobody is touching, reads
# the same as the fin behind which it hangs (#570), which is how a player tells a
# deflecting surface from one merely carried through the air (worst disagreement 0.2 deg
# all the way through).
CHECK all(abs(f + g) < 1.2 for f,g in zip([s["a"] for s in surface][4::10],[d["beta"] for d in drag]) if abs(g) > 4.0)
CHECK all(abs(f - r) < 0.6 for f,r in zip([s["a"] for s in surface][4::10],[s["a"] for s in surface][7::10]))
# A sideslip is not allowed to leak into pitch: the wings stay 2.5-2.9 deg through the
# kick, and the fin, which reads 0 when the ship points into the flow, reads 0 again
# once it does -- every row from t=44 s on prints 0.0 or -0.0 on this run, so the 0.3
# band below is slack for phase rather than a measured margin.
# The filter used to be Beta, and #503 showed what that was really sampling. At t=29 s
# the swing has all but come back (Beta +1.0) and the fin still reads -0.6 deg: its
# angle is not the ship's. The fin stands 2.2 m aft of the COM and the rudder 3.1
# (#568's stack put them a metre further back than the spindle did, and #570 hung the
# rudder off the fin's own trailing edge), and the yaw rate that carried Beta through its
# crossing -- 12.5 deg/s at t=27 s, off the att log -- drags 0.47 m/s of air sideways
# across the fin and 0.67 m/s across the rudder, which at the 58 m/s this kick is flying
# at is 0.5-0.7 deg: the 0.4 deg the fin still claims at that row. #483's sweep term
# doing its job on an airframe that is pointing into the flow while still turning. The
# rate is slower than the 12 m wing showed at the same instant (12.5 deg/s against
# 18.0 at t=27 s), but the swing sits at a different phase two tickets on, so read that
# as #567 putting 96 kg of wing out to an 8 m tip and the hull's yaw inertia with it
# rather than as a measured ratio.
# Those row numbers (12.5 deg/s, 58 m/s, Beta +1.0 at t=29 s) are the pre-#686 run's:
# the denser bed air moved the whole swing along the phugoid, so re-read the rows before
# quoting any of them again. The 0.3 band they argue for still holds -- every settled row
# from t=44 s on reads 0.0 on this run.
# #503's weaker full-lock rudder made the swing quicker, so the 1 s sample now lands on
# that crossing; before, the same instant read Beta=-0.5 and fell out of the filter.
# Betting a band on where one sample lands inside an oscillation is a bet on phase, not
# on the law (453 argues the same about its own swing), so the window is now time-based
# and the band itself stays at 0.3.
# The wing band used to be 2.2..3.6, a 1.4 deg window around a signal that measured
# 2.5..2.7 on every row of this run -- a band that could not fail for a sideslip leaking
# into pitch. It is 2.4..3.4 now: the run measures 2.50..3.20, so 0.1 deg of slack below
# and 0.2 above, and the leak this pins is a fraction of that. The top of the signal is
# what moved when the air started moving (#688): at t=25 s the hull is slipping into the
# kick at 30 m/s of AIR, so a metre per second of sweep across a 4 m half-span is 1.9 deg
# of angle where the same turn reads 0.7 deg at 78 m/s.
CHECK all(2.4 < a < 3.4 for a in [s["a"] for s in surface][0::10])
CHECK max(abs(f) for f,t in zip([s["a"] for s in surface][4::10],[d["t"] for d in drag]) if t >= 44.0) < 0.3
# q is the pressure of the flow AT the surface (#483), not one ship-wide number, and the
# log shows it: the widest wing-tip split of this run is 15 Pa (t=30 s reads 444 on
# wing_l and 459 on wing_r) and the split FLIPS SIGN with the yaw -- t=28 reads wing_l 284
# over wing_r 270, t=30 the other way -- which is omega x r across a 16 m span, a metre or
# so per second of sideways flow at the tip while the hull is turning
# through its kick. The same row spans 21 Pa across all ten parts: the two
# outermost plates pay the sweep and the ones near the rotation axis do not, so the row
# spread is always at least the tip split. A quiet row prints all ten parts within 1 Pa
# of each other.
# The split used to measure 35 Pa. It is a pressure DIFFERENCE, and a pressure difference
# from a given sideways speed is rho * v_air * (omega x r): the same turn at half the
# AIRSPEED pays half the split. Hence the floor moves from 30 Pa to 10 -- measured 15, so
# a third of slack, and the sign flip above is the part that cannot happen at all if the
# flow stops being per-part.
# Sampled on every part of every row rather than one survivor: the shared band against the
# air's OWN speed is 0.96..1.05 across all 500 values, the residual being the substep
# between the aero pass and the log line plus that per-part spread.
# It has to be the air's speed, not the row's |v|: since #688 the air moves, and the [drag]
# line documents that its |v| is live GetVel() while Mach is over the air-relative speed
# (tick.cpp). Kerbin authors 5 m/s at the deck ramping to 40 m/s at 11 km, so at this
# 8.5 km cruise the two differ by roughly 30 m/s and 0.5*rho*|v|^2 is a factor 2.5 off the
# q every part actually pays -- which is exactly what this CHECK used to pass on. Rebuild
# the air-relative speed from the row's own Mach x airA (29.95..78.27 m/s against an
# inertial 59.31..104.47) rather than adding a field to a line whose parsers are older
# than most of its columns.
# (The inner comprehension repeats each drag row once per part: [surface] flattens ten
# parts onto one row, and the CHECK sandbox has no range().)
CHECK all(0.92 < sp["q"] / (0.5 * d["rho"] * (d["mach"] * d["airA"]) ** 2) < 1.08 for d, sp in zip([r for r in drag for _ in surface[0:10]], surface))
# ... and the twins disagree where they should: the wing pair's q is not one number.
# This one reads the mirrored wing pair only -- 15 Pa measured against a 10 Pa floor, so
# it reddens if a per-part flow stops being per-part.
CHECK max(abs(l["q"] - r["q"]) for l, r in zip(surface[0::10], surface[1::10])) > 10.0
