# #876's pad complaints -- "panning left and right then rolls the camera", "the
# other side view is upside down", "can't go below the horizon" -- are
# orientation, and --cam-log used to print none of it, so the issue could only
# be argued from impressions. It now prints pole (the angle between the
# turntable's yaw axis and the local vertical), roll (how tilted that vertical
# reads on screen) and camh (the camera's height above the horizontal plane
# through the ship's COM), and this case pins the SHAPE OF THE BUG in numbers:
#   pole=90 deg in every row. The ship-focus turntable's yaw axis is ref's
#     third column -- ship axis 1, the vector refreshWorld's ship-focus branch
#     labels "up" -- which for a landed rocket is HORIZONTAL. The turntable's
#     pole, where the projected up vanishes, sits on the horizon.
#   pin=hi: Pitch()'s 1.52 rad clamp bites exactly there. That is the wall
#     "panning down" hits, and why the view never gets under the horizon.
#   roll 0 -> ~172 deg across a left/right drag while fwd moves by less than
#     0.3: at that clamp the view line runs along the yaw axis, so panning
#     left/right rolls the whole image instead of orbiting it. roll is
#     ill-conditioned at the OTHER pose (pitch 0, straight down the mast: no
#     horizon in the picture) and its noise moves between runs -- measured
#     +27.9/+149.6/-88.7 on one boot and +27.9/+107.2/-116.9 on another -- so
#     every roll filter here also requires pin=="hi", never roll alone.
#   camh -0.5 m: what crossing that stop does in the world -- the camera ends
#     up under the plane the ship's COM sits in.
# Deliberately golden. When the camera frame blends toward the local vertical,
# pole and roll both go to ~0 and this case is updated to assert THAT: flipping
# these numbers IS the fix. --cam-gizmo rides along because nothing else
# exercises that overlay, and the default GL_/Assertion forbids then catch it
# drawing nothing but errors.
NAME pad-camera-turntable-pole
CLAIM A landed ship's turntable yaw axis sits 90 deg off the local vertical, so a left/right drag at the pitch clamp rolls the image instead of orbiting it.
KIND golden
ARGS --timeout 6 --time-accel 1 --startship racer,res/ships/racer.json,Kerbin,pad --cam-log --cam-gizmo --orbit-interval 0.25
ARGS --sim-mouse 1000,0,900,500,0
ARGS --sim-mouse 1200,800,900,900,RMB
ARGS --sim-mouse 2500,1000,1500,900,RMB
EXPECT [camlog]
CHECK all(r["lv"] is not None for r in cam)
CHECK all(r["mode"] == "orbit" and r["pole"] is not None and abs(r["pole"] - 90.0) < 1.0 for r in cam)
CHECK sum(1 for r in cam if r["pin"] == "hi" and r["roll"] is not None and abs(r["roll"]) < 0.5) >= 2
CHECK sum(1 for r in cam if r["pin"] == "hi" and r["roll"] is not None and abs(r["roll"]) > 160.0) >= 2
CHECK max(abs(a["fwd"][0] - b["fwd"][0]) + abs(a["fwd"][1] - b["fwd"][1]) + abs(a["fwd"][2] - b["fwd"][2]) for a in cam if a["pin"] == "hi" and a["roll"] is not None and abs(a["roll"]) < 0.5 for b in cam if b["pin"] == "hi" and b["roll"] is not None and abs(b["roll"]) > 160.0) < 0.3
CHECK any(r["camh"] is not None and r["camh"] < 0.0 for r in cam)
FORBID error:
LIMIT 60
