NAME drag-log-lift-readings
CLAIM The --drag-log's signed lift and attitude readings parse in flight and stay inside their bounds.
KIND harness
ARGS --time-accel 1 --startship skiff,res/ships/skiff.json,Kerbin,flying-cruise
ARGS --timeout 20 --drag-log
ARGS --sim-press 1000,2000,R
ARGS --sim-press 1500,4000,T
ARGS --sim-press 6000,1500,W
EXPECT [drag]
CHECK len(drag) >= 5
CHECK any(d["F"] > 0 and d["rho"] > 0 for d in drag)
# L_up (the lift part . local vertical) and Up (the airframe's own up axis .
# local vertical), both from #448. Every row carries them; Up is a cosine and
# L_up a COMPONENT of the printed |L|, so both bounds are hard -- a dot taken
# between mismatched frames or against the wrong vector shows up here as a
# component larger than its magnitude.
CHECK all(("L_up" in d and "up" in d) for d in drag)
CHECK all(abs(d["up"]) <= 1.0 + 1e-9 for d in drag)
CHECK all(abs(d["L_up"]) <= abs(d["L"]) + 1e-6 for d in drag)
# And the lift part never outweighs the whole aero force it came from. A tell rather than
# a law -- each surface stands in its OWN flow (#483), so a hull that pitches hard enough
# for w x r to matter leaks across the split -- but on this hull the ratio never got above
# 0.988, and before #699 put the control loop's deflection force into the sum it ran over
# 1.0 on hulls trimmed enough to need a tab (flight/492 pins the trimmed case).
CHECK all(d["L"] <= d["F"] for d in drag)
CHECK any(d["L"] > 400 and abs(d["L_up"]) > 100 for d in drag)
# This hull has a jet and no rocket, so it has to fly on air it can BURN, which since
# #630 means air with an oxidizer in it: the case used to spawn on Duna, whose air is
# 95% CO2 with a 0.13% oxygen trace, so the skiff's fan is worth a rounding error of
# its rating there -- the gate's oxidizer half ends it (#637), and #700 made that
# column another 8x thinner at the ground, 0.118 kg/m3 at the old bed becoming 0.0094
# at the new one -- it never leaves the pad, so no lift row reaches the bound and the
# whole case goes red on a hull that is behaving correctly. Kerbin has dry air, so its
# jet works there; nothing about what this case asks changed. It also starts FLYING
# rather than on a pad, because the same hull is 569 kg on Kerbin's 9.81 m/s2 and its
# 5625 N fan cannot lift it off the ground -- the pad departure was only ever possible
# on a low-g body, which is what flight/490's Kerbin cruise spawn has been using all
# along.
#
# The magnitudes are what this departure actually makes -- and both of this window's
# changes moved them, so this row of prose is a measurement, not a memory. #686 moved the
# flying-cruise bed from 7 km to 8.5 km (0.1 x the 85 km top), so the hull now flies in
# 0.496 kg/m3 rather than 0.34; #699 put the control loop's deflection force into |L|,
# which on this untrimmed hull means the rudder's side force joins the sum. The 20 rows
# this run prints sit at 8502-8759 m over 25.1-77.1 m/s; all of them clear both bounds and
# the biggest is t=6.9 s -- |L| 14395 N with L_up +11999 N at 64.34 m/s. Those figures are
# one wall-clock-gated run, not a pin: --timeout 20 means a slower box prints fewer rows and
# a faster one more, and a repeat run moved the peak row by ~0.4 %. The CHECKs are bounds,
# not numbers. The 1000 N this used to ask
# for belonged to the heavier spindle hull #568 replaced; the 559-569 N with L_up
# -217..-219 N was the 12 x 1.8 wing, and #567 moved the peak by a few tens of N without
# moving what the bound means. What is pinned is that a real component of a real force
# appears, not the airframe's size -- and since #699, that the lift part never outweighs
# the whole aero force it came from (flight/492 pins that on a trimmed hull, where it is a
# 13 % question rather than a rounding one).
# The SIGN law -- a wing above the flow lifts -- is NOT pinned here and cannot
# be: aoa and L_up are both odd in alpha, so any relation between them is even
# under a sign flip. tests/test_drag's test_wing_lifts_up pins it, in a frame
# where the geometry is known. A real "plane flies" golden needs #451 first.
