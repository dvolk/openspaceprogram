# The type dropdown picks WHICH law the shared buttons act on (#612). The window
# used to show Ascent, Descent and Transfer stacked, each with its own prose; now
# one combo selects a section and there is one Go and one Cancel for all of them.
# What that buys, and what it must not break, is the whole case: a type with no
# law greys Go and shows no ask fields of its own instead of offering inputs that
# would do nothing; switching type while a mission flies must still leave a way to
# stop it, because the Cancel button is shared and the mission is not per-tab.
# --sim-steps makes the click timestamps logic ticks rather than wall ms (as in
# ui/424), so the arming order below does not move with machine speed. The combo's
# popup is imgui's own window, ##Combo_00, whose rows carry the item labels; it is
# named by popup DEPTH and imgui resets that counter each NewFrame, so the path
# does not drift with how many combos were drawn before it.
# --ui-list 2100 dumps the live widgets while Transfer is the selected type. A
# section's prose is drawn, not printed, so the row list is the only place its
# shape is visible -- and this is the one moment between picking Transfer (1800)
# and opening the combo again (2200).
NAME guidance-window-types
CLAIM The type combo gates Go per law and swaps its section out, and the shared Cancel still stops a mission seen from another type.
KIND invariant
ARGS --startship racer,res/ships/racer.json,Moho,pad --time-accel 10
ARGS --ascent-log --timeout 120
ARGS --sim-steps 1500
ARGS --ui-click 800,"Windows/Autopilot"
ARGS --ui-click 1200,"Autopilot/Guidance"
ARGS --ui-click 1600,"Guidance/type"
ARGS --ui-click 1800,"##Combo_00/Transfer"
ARGS --ui-list 2100
ARGS --ui-click 2000,"Guidance/Go"
ARGS --ui-click 2200,"Guidance/type"
ARGS --ui-click 2400,"##Combo_00/Descent"
ARGS --ui-click 2600,"Guidance/Go"
ARGS --ui-click 2800,"Guidance/type"
ARGS --ui-click 3000,"##Combo_00/Ascent"
ARGS --ui-click 3200,"Guidance/Go"
ARGS --ui-click 3400,"Guidance/type"
ARGS --ui-click 3600,"##Combo_00/Transfer"
ARGS --ui-click 3800,"Guidance/Cancel"
LIMIT 60
# The two greyed-out Go clicks land as refusals: --ui-click refuses a disabled
# widget rather than clicking empty space, so the refusal line IS the assertion.
EXPECT path="Guidance/Go" FAILED disabled
# ...and switching to Transfer did not strand the mission: Cancel is shared, and
# the mission belongs to the hull, not to the tab it was armed from.
EXPECT [toast] Guidance: ascent armed on 'racer'
EXPECT [toast] Guidance: ascent cancelled -- hand-flown
FORBID phase=done
CHECK out.count("FAILED") == 2
# Exactly one arming, from the Ascent section. Transfer and Descent armed
# nothing even though the buttons are the same buttons.
CHECK sum(1 for t in toast if "ascent armed" in t) == 1
# What the Transfer section draws, from the dump above: it keeps the buttons that
# are shared with every type and offers no ask fields of its own. Matched on
# labels, not rects, so a font or layout change cannot break it -- the claim here
# is which widgets exist, not where they sit.
CHECK 'window="Guidance" label="Go"' in out
CHECK 'window="Guidance" label="Cancel"' in out
CHECK 'label="PeA (km)"' not in out
