# The hull card's aero block (#1090, restyled by #1113): the union silhouette bills
# the ship ONCE, but the #945 partition keeps the score by part, and the silhouette
# cache nodes carry that partition so the per-part numbers exist on chart hits too.
# Right-click the pod and the tank of a cruising skiff -- both body parts -- and
# each card now prints the surface block's three-row shape:
#   "Form: <m2> visible  cd <cd>  hides <pct>%  side <m2> m2"   the credit (#1090,
#                                                  + the #1105 crossflow pair)
#   "Hull AoA: <deg>  q=<Pa>  Mach <M>"   the flow that bill is struck in
#   "Drag power: <W> (peak <W>)"          the watt share, model-peak beside it
# on the #734 instrument cadence. The OSP_SHIP_DUMP audit showed these numbers one
# flag away (at alpha 0 the pod keeps the whole union, visA 0.78 = unionA, and the
# sheltered tank 0.00); this puts them where the player can ask.
#
# #1113 changes what "disjoint" looks like: the body card's q/Mach are the BILL's
# flow (lfCp at the cp -- part.h says "an accounting share, not a local bill"), so
# the three rows multiply together, and a MOUNT-sampled q was rejected exactly for
# not multiplying back. "Drag power" is therefore a shared label now -- disjointness
# is pinned instead by the surface block's "AoA:" row never appearing on a body
# card (the hull's angle prints as "Hull AoA:", which is the airframe angle the
# credit was billed at, not an invented per-part incidence -- #732's rule).
#
# What this case does NOT pin: the dashed fallbacks (the air-boundary row triples).
# Their cells come from the same helpers and constants the live rows use --
# partFlowRow/partPowerRow, wattCell's own dash spelling, kFormVisDash
# static_asserted to the live vis cell -- so cells cannot DRIFT from the live row
# by accident. The row COUNTS and the exact dashed spellings are pinned by the
# sibling ui/1115-a: above the air, not parked (every shipped atmosphere authors
# wind, so the pad prints live rows -- #1115's premise, corrected by audit).
#
# WHY THE BED IS flying-trim (#1201, 2026_11_26): this case used to open on
# flying-cruise, and by the time these eleven dumps run that bed has the hull
# mid-zoom-climb -- +14.2 deg ramping to +20.7 with q falling 35 -> 22 Pa, exactly
# the over-trimmed opening vehicle.cpp:332 admits to ("~1.9x" the trim point, #693).
# Every figure on the card then LEGITIMATELY sweeps: pod credit 0.76 -> 0.88 m2,
# tank shelter 66.1 -> 41.5 %. That made the cadence guard below (at most 5 distinct
# pod rows in 11 reads) fail for the wrong reason -- the panel is held, the air is
# moving. So the fixture moved rather than the band, because everything above
# describes a steady cruise. On #693's airframe-keyed load bed the same 11 reads see
# ONE pod row (0.77 m2, cd 0.36) and the tank's shelter holds at 77%, which is the
# #1105 claim the case was written around.
NAME hull-card-form-row
CLAIM Body part cards print the merged aero block -- credit row, hull flow row, watts row -- at cadence; the hull flow row agrees across the ship's body cards; the upwind capsule reads a real area and cd; no surface AoA row on body cards.
KIND invariant
ARGS --time-accel 1 --sim-steps 600 --width 1920 --height 1080 --startship skiff_trim,res/ships/skiff_trim.json,Kerbin,flying-trim
ARGS --ui-focus 2000,skiff_trim/pod
ARGS --sim-mouse 2200,0,CUR,CUR,RMB
# The tank sits behind the pod along the flight line -- that occlusion IS the story
# (the audit at alpha 0 credits the tank 0.00 for exactly this reason) -- so the
# chase camera cannot aim at it: orbit like a player (harness/281's RMB drag) and
# aim again.
ARGS --sim-mouse 2600,800,960,300,RMB
ARGS --sim-mouse 3400,0,960,620,0
ARGS --ui-focus 4200,skiff_trim/tank
ARGS --sim-mouse 4400,0,CUR,CUR,RMB
ARGS --ui-list 6000 6100 6200 6300 6400 6500 6600 6700 6800 6900 7000
EXPECT [uilist] loop=
# One row of each per read per card, and exactly the two body cards print them.
CHECK len([r for r in uilist if r["label"].startswith("Form:")]) == 11 * 2
CHECK len({r["window"] for r in uilist if r["label"].startswith("Form:")}) == 2
CHECK len([r for r in uilist if r["label"].startswith("Hull AoA:")]) == 11 * 2
CHECK len([r for r in uilist if r["label"].startswith("Drag power")]) == 11 * 2
# The surface block's OWN AoA row still never appears on a body card -- that is the
# player-visible half of the disjointness claim now that "Drag power" is shared.
CHECK not any(r["label"].startswith("AoA:") for r in uilist)
# Cadence (#734): eleven reads 100 ms apart see the PUBLISHED figures, never more
# than a couple of them. The lower bound is deliberately 1 here: unlike the wing
# loads (0.7..39 kW across the trim porpoise in 734), a pod's frontal credit barely
# responds to that oscillation -- 0.78 m2 and 8.9 kW round steady -- so one distinct
# figure is honest physics, not a frozen panel. The UPPER bound is the guard: with
# the hold gone the row repaints from every frame's live figures, and this row
# prints to quarter-watts (945.3 W) on a porpoising hull -- it cannot repaint
# steady, which is how 734 caught the shared-state bug at 11 distinct figures.
CHECK 1 <= len({r["label"] for r in uilist if "Capsule (1m)" in r["window"] and r["label"].startswith("Form:")}) <= 5
# One hull, one frame (#1114): at every dump stamp, all body cards print the SAME
# flow row -- the window and its published sample live on the HULL (Vehicle::
# hflow, worst frame by lastFormWatts, kReadSec grid), not per card. Before the
# fix every dump disagreed (tank q=455 vs pod q=572, alpha +4.8 vs +4.7 in the
# SAME dump -- and it FLAKED: whether cards agreed depended on when they opened
# against the sim ending). Whole label equality is exact here: the row carries
# no part-specific text and both cards print one published sample.
CHECK all(len({r["label"] for r in uilist if r["label"].startswith("Hull AoA:") and r["t"] == t}) == 1 for t in {r["t"] for r in uilist if r["label"].startswith("Hull AoA:")})
# The column holds: fixed-cell figures print the same character count every read.
# (Only the two rows whose cells are ALL fixed: the watts cells are wattCell's
# 9 chars, and the Form row's cells are vis %6.2f, cd %4s, hides %5.1f%% and side
# %6.2f (#1105), all four mirrored by static_asserted dashes. The flow row's q= is
# %0f and legitimately varies width as dynamic pressure varies -- the surface
# block's own flow row has the same property, and ui/734 pins its q= OFFSET
# instead, which this row's "Hull " prefix deliberately cannot collide with.)
CHECK len({len(r["label"]) for r in uilist if r["label"].startswith("Form:")}) == 1
CHECK len({len(r["label"]) for r in uilist if r["label"].startswith("Drag power")}) == 1
# The pod is the upwind-most body of the stack, so every pod read carries a real
# credit -- area >= 0.3 m2 (its own silhouette is ~0.8) and a NUMERIC cd. A sheltered
# part would dash the cd cell; the pod never may.
CHECK all(re.search(r"Form:\s+([0-9.]+) m2 visible  cd \d", r["label"]) and float(re.search(r"Form:\s+([0-9.]+) m2", r["label"]).group(1)) >= 0.3 for r in uilist if "Capsule (1m)" in r["window"] and r["label"].startswith("Form:"))
# Every row parses on both cards: the cd cell is numeric or the four-char dash.
CHECK all(re.search(r"Form:\s+[0-9.]+ m2 visible  cd (   -|\d+\.\d+)", r["label"]) for r in uilist if r["label"].startswith("Form:"))
# #1105: the two crossflow cells, read off the same two cards. The occlusion this case
# is built around (the tank behind the pod along the flight line) was already half-visible
# here -- the tank keeps a sliver of credit -- but nothing showed HOW much of it the pod
# ate, and none of the hidden area's sideways bill appeared at all. Now the pod, the
# upwind-most body, reads 0.0% hidden and 0.00 m2 at every read (nothing hides anything
# from it, so the axial bill already paid its flank), and the tank behind it reads well
# over half hidden WITH a side figure beside it, because this hull authored drag_side on
# its tank.
# Deliberately NOT pinned, even though the run shows them: hidden == 100.0%, the
# measured 93.5% / 0.17 m2 (fixture geometry), and "hidden implies a side figure" -- that
# last one is a fact about res/data/parts.json, not about #947. Refusal alone bills
# nothing, because cn is authored and never defaulted; the unit bench holds that case on
# its own parts, where a 10.3%-hidden shelter reads 0.0000 m2 beside it.
CHECK all((lambda l: float(re.search(r"hides\s+([0-9.]+)%", l).group(1)) == 0.0 and float(re.search(r"side\s+([0-9.]+) m2", l).group(1)) == 0.0)(r["label"]) for r in uilist if "Capsule (1m)" in r["window"] and r["label"].startswith("Form:"))
CHECK all((lambda l: float(re.search(r"hides\s+([0-9.]+)%", l).group(1)) > 50.0 and float(re.search(r"side\s+([0-9.]+) m2", l).group(1)) > 0.0)(r["label"]) for r in uilist if "Fuel Tank" in r["window"] and r["label"].startswith("Form:"))
# The flow row carries the hull's angle and the bill's flow, live on both cards --
# a signed angle cell (formatAlphaDeg), a numeric q and Mach (never dashed while
# this in-air case runs).
CHECK all(re.search(r"Hull AoA:\s+[-+][0-9.]+ deg\s+q=[0-9]+ Pa\s+Mach [0-9.]+", r["label"]) for r in uilist if r["label"].startswith("Hull AoA:"))
# And the watts row parses with a peak beside it (the peak may round to the same
# figure as the held value on this steady cruise -- that is honest, not frozen).
# The \s+ before "(peak": wattCell's 9-char cell can carry a trailing space.
CHECK all(re.search(r"Drag power:\s+[0-9.]+ [kMWG]*W\s+\(peak .+\)", r["label"]) for r in uilist if r["label"].startswith("Drag power"))
FORBID error:
