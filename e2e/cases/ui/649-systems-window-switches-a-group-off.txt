# Flight gets a Systems window (#649), and with it the two things the electrical system
# never had: a home for the power breakdown that is not the Game Debug overlay, and a
# handle for doors the sim has been honouring for tickets now.
#
# The rows themselves are not new -- #601 made them readable and #642/#643/#648 decided
# what they mean. What is new is where they live: the balance used to sit at the bottom of
# the F1 overlay, so a player who never pressed F1 watched the EC bar in Resources drain
# with no word about why, and #646 filed that as a bug in its own right. Systems is a
# window listed in the Windows panel; the 2026_11_05 UI pass made it CLOSED by default
# (a panel you consult, not an instrument you scan, and it will only grow), so the clicks
# below open it, close it and open it again -- the panel row answers both ways, which is
# the case proving the listing rather than trusting the WinDef table.
#
# The switch is the other half. Vehicle::wheels_enabled has been load-bearing since #425
# D-2 -- wheelsPowered() is the one predicate the row builder, the slew laws, the Vessel
# rows and the EC bill all consult -- but NOTHING in the game ever wrote it, so the door
# had no handle. Flipping it takes the drums out of the capability model exactly as a dead
# battery does (test_authority pins the sim half: no rows, no torque billed, the ask
# rerouted to the gimbals). What this case pins is the readout half, and the pair of
# states that have to be true on either side of the click -- which is why --ui-list is
# repeatable (#649): one dump could only show the after picture, so the case would assert
# the door closed while trusting the door had been open.
#
# WHERE each half is pinned changed on 2026_11_05. The VALUE of the claim -- live
# authority 4950 N m becoming 0 -- is read from --steering-log rather than off a text row:
# a value belongs in a log, and a window's wording belongs to whoever is next polishing
# the window (the 2026_11_05 e2e policy). [steerlog] prints the same pair the window does,
# from the same calls: wheels= is attitudeAuthority() (a shut switch answers 0) and
# wheels_hw= is attitudeAuthorityHardware() (enable switches ignored), which is why a
# switch can name what it gives up without a third arithmetic (#575). wheels_on= is the
# flag itself, so a 0/0/0 row says which door shut -- power, switch, or no drums fitted.
#
#   before: [steerlog] wheels_on=1  wheels=4950/4950/4950 wheels_hw=4950/4950/4950
#           Systems      on   4950 / 4950 / 4950 N m (R/P/Y)
#   after:  [steerlog] wheels_on=0  wheels=0/0/0           wheels_hw=4950/4950/4950
#           Systems      off  4950 / 4950 / 4950 N m (R/P/Y)
#
# The UI half stays, because that IS the feature: a switch with no figure beside it is a
# switch nobody is willing to touch. The row's "at stake" gloss is gone (values, not
# prose), and so is this case's F1 press -- the steering DETAIL rows moved out of Vessel
# Info into Game Debug in that same UI pass, but the numbers above no longer need a window
# to be open at all.
#
# The aero switch's row is pinned too, and pinned to the RIGHT reason. power_test carries
# no fins at all, so its aero row is "no aero surfaces on this hull"; the first printing
# of this window said "no air for them to push" for every hull with an empty surface set,
# which told a rocket sitting in full air that its sky was the problem (#649's review
# pass). Empty-with-fins and never-any-fins are different news, and the row builder now
# records which hull it is.
#
# The third switch is the RCS ring's, and it arrived with #595 -- this window could not
# build it while the ring had no attitude authority to quote beside it (the ticket's own
# rule: print a figure, never a third arithmetic). power_test carries no pods, so its ring
# row reads "no thruster pods on this hull": the fitting, not the switch and not the tank,
# which is hw.hasRcs rather than the empty row the row builder returns for all three
# reasons. The window's row count moved 8 -> 9 with it, and the count is pinned below
# because "one row per switch group, whatever the group's state" is the whole design.
#
# The fourth door (#768) is the nozzles, and it moved that count 9 -> 10. power_test's
# engine_r2.25h4.5 IS gimballed (res/data/parts.json, 0.0873 rad at 1.5708 rad/s), so
# unlike the fins and the ring this hull has something to vector: the row quotes
# 129710 N m -- the ignited stage's rated thrust through this hull's own stack lever and
# sin(gimbal_max), the same product --steering-log prints as tvc_rating_full (and as
# tvc_hw, which is the same figure with the enable switches ignored). What the switch
# itself does is pinned by ui/768-systems-window-shuts-the-nozzles; here it only has to be
# PRESENT, because a row that appears and disappears with the group's state is the failure
# this window was designed against.
NAME systems-window-switches-a-group-off
CLAIM The Systems window is listed in the Windows panel and prints the EC balance, and its Reaction wheels checkbox drops the live authority in --steering-log from 4950 N m to 0 while the row still quotes the 4950 N m the switch gives up.
KIND golden
ARGS --width 1600 --height 900 --timeout 12 --steering-log
ARGS --startship power_test,res/ships/power_test.json,Kerbin,rot-orbit
ARGS --ui-click 2000,"Windows/Systems"
ARGS --ui-click 2600,"Windows/Systems"
ARGS --ui-click 3100,"Windows/Systems"
ARGS --ui-list 3400
ARGS --ui-click 4000,"Systems/Reaction wheels"
ARGS --ui-list 5000
EXPECT [uilist] window="Systems" label="Const draw: 600.0 W   (life support)"
EXPECT [uilist] window="Systems" label="  on   4950 / 4950 / 4950 N m (R/P/Y)"
EXPECT [uilist] window="Systems" label="  off  4950 / 4950 / 4950 N m (R/P/Y)"
EXPECT [uilist] window="Systems" label="  on   no aero surfaces on this hull"
EXPECT [uilist] window="Systems" label="  on   no thruster pods on this hull"
EXPECT [uilist] window="Systems" label="  on   129710 N m (pitch/yaw disk)"
FORBID FAILED
FORBID error:
# The model's own answer, either side of the click, and in that order. Both columns on one
# row: the live figure moved and the hardware figure did not, which is the pair the window
# is built to show.
CHECK re.search(r'\[steerlog\][^\n]*wheels_on=1 [^\n]*wheels=4950/4950/4950 wheels_hw=4950/4950/4950', out)
CHECK re.search(r'\[steerlog\][^\n]*wheels_on=0 [^\n]*wheels=0/0/0 wheels_hw=4950/4950/4950', out)
CHECK out.index('wheels=4950/4950/4950') < out.index('wheels=0/0/0')
# Per dump, not per run: two --ui-list times means two dumps, and each has to carry the
# whole window -- Status, five power rows and one row per switch group (four of them since
# #768's nozzles). A row that vanished with the door closed, which is the mistake this
# window's design is about, shows up here as 10 then 9 rather than as a 19 that still looks
# plausible.
CHECK [len([l for l in d.split("\n") if l.rstrip().endswith(" text") and 'window="Systems"' in l]) for d in out.split("[uilist] loop=")[1:]] == [10, 10]
# Vessel Info is down to one row -- the Angular rate that says whether the hull is
# turning. The per-axis actuator rows it used to carry (drums, gimbals, fins) all moved to
# Game Debug in the 2026_11_05 pass, so this count no longer depends on the part list; the
# numbers this case cares about come from the log, which needs no window open at all.
CHECK [len([l for l in d.split("\n") if l.rstrip().endswith(" text") and 'window="Vessel Info"' in l]) for d in out.split("[uilist] loop=")[1:]] == [1, 1]
# Two dumps, and two DIFFERENT moments. A --ui-list time fires on the first frame at or
# after it, so two times inside one frame gap would print the same picture twice and the
# [10,10] above would prove nothing. The stamps are printed; pin them apart, with a margin
# wider than a frame (16ms) but far inside the 1.6s between the click and the second dump.
CHECK len(re.findall(r'^\[uilist\] loop=([0-9.]+)s', out, re.M)) == 2
CHECK float(re.findall(r'^\[uilist\] loop=([0-9.]+)s', out, re.M)[1]) - float(re.findall(r'^\[uilist\] loop=([0-9.]+)s', out, re.M)[0]) > 0.5
