# #1027: what an auto-stage refusal says. The note that explains WHY a stack cannot be
# numbered runs past 160 characters -- measured live at 2419 px of text against a 1920
# viewport, so at 1280 a player reads the middle of the sentence and loses the end of it.
# A player cannot act on "the tree cannot see a core that burns the whole flight", so the
# banner now says one short thing and the technical note goes to the log under
# [autostage] -- the same text --fleet-report prints. The distinction is checkable because
# the `toast` list is what Game::toast mirrors, i.e. exactly what got painted.
#
# heavy_asp is the hull that walks into it: it lights engine_central from the pad, and the
# stack's shape would hand that core to a later press (#1020 is the WIP that lets it through).
#
# No --width/--height: a small window stops the VAB top bar taking clicks (#1017), and
# every step here is a click.
NAME an-auto-stage-refusal-says-one-short-line-and-logs-its-reason
CLAIM Auto-stage on a stack it refuses toasts one short line and logs the technical reason instead of painting it.
KIND invariant
ARGS --ui-click 1000,"Title Menu/New Game"
ARGS --ui-click 1600,"New Game/Start"
ARGS --sim-press 2600,0,4
ARGS --ui-type 3200,"VAB TopBar/##vehfilter",heavy_asp
ARGS --ui-click 3800,"VAB TopBar/##vabload"
ARGS --ui-click 4400,"heavy_asp"
ARGS --ui-click 5000,"VAB TopBar/Load"
ARGS --ui-click 5600,"Staging/Auto-stage"
ARGS --stage-dump 6400 --timeout 14
LIMIT 60
EXPECT [vab] loaded heavy_asp (45 parts)
# What the player sees: one line, and the build is left alone.
EXPECT [toast] Can't auto-stage this ship
# What the log keeps: the same sentence the refusal used to paint.
EXPECT [autostage] refuse: 'engine_central' lights at launch as built
CHECK all("refuse:" not in t for t in toast)
CHECK max(len(t) for t in toast if "auto-st" in t.lower()) < 72
FORBID error:
FORBID FAILED
