# #1027: what the Auto-stage button says. Its plan notes explain the SHAPE of the stack --
# which part, which label, what the tree cannot see -- and they run past 160 characters, which
# in the toast font (2x --font-size, ~16.8 px per mono cell) is about twice the width of a 1280
# screen: the player reads the middle of a sentence and loses the end of it. The notes now go
# to stdout under [autostage] -- the same text --fleet-report prints -- and the banner carries
# one short line. The tag is deliberately not [toast], because Game::toast's mirror is what the
# harness reads as "what the player saw".
#
# Three clicks, one per outcome the button has:
#   rootcut        refused: its only decoupler would have to take the whole ship, and that press
#                  is refused in flight, so the label would be spent on nothing (#541)
#   skiff          refused for the commonest reason of all -- no decoupler anywhere, 25 of the
#                  32 shipped hulls -- where "can't" would call a one-stage ship broken
#   central_radial applied, with a note that two engines that shared a label now light apart:
#                  a real change, still detail, so it is a log line and not a second banner
#
# rootcut and central_radial need Game Debug's dev-vehicles switch (a fixture, a testship),
# flipped once and left on. No --width/--height: a small window stops the VAB top bar taking
# clicks (#1017), and every step here is a click.
NAME auto-stage-says-one-short-line-and-logs-its-detail
CLAIM Auto-stage toasts one short line per outcome and logs its technical detail instead of painting it.
KIND invariant
ARGS --ui-click 1000,"Title Menu/New Game"
ARGS --ui-click 1600,"New Game/Start"
ARGS --sim-press 2600,0,4
ARGS --sim-press 3200,0,F1
ARGS --ui-click 3700,"Game Debug/Dev vehicles in the VAB picker"
ARGS --sim-press 4200,0,F1
ARGS --ui-type 4700,"VAB TopBar/##vehfilter",rootcut
ARGS --ui-click 5300,"VAB TopBar/##vabload"
ARGS --ui-click 5900,"rootcut"
ARGS --ui-click 6500,"VAB TopBar/Load"
ARGS --ui-click 7100,"Staging/Auto-stage"
# Dump once, while the refused build is still up: the plan is not just quiet, it left the
# decoupler on label 1 -- the label that has no press under it.
ARGS --stage-dump 7700
ARGS --ui-type 8500,"VAB TopBar/##vehfilter",skiff
ARGS --ui-click 9100,"VAB TopBar/##vabload"
ARGS --ui-click 9700,"skiff"
ARGS --ui-click 10300,"VAB TopBar/Load"
ARGS --ui-click 10900,"Staging/Auto-stage"
ARGS --ui-type 11700,"VAB TopBar/##vehfilter",central_radial
ARGS --ui-click 12300,"VAB TopBar/##vabload"
ARGS --ui-click 12900,"central_radial"
ARGS --ui-click 13500,"VAB TopBar/Load"
ARGS --ui-click 14100,"Staging/Auto-stage"
ARGS --timeout 18
LIMIT 70
EXPECT [vab] loaded rootcut (3 parts)
EXPECT [stagetree] 0 dec_root def=decoupler_r1 parent=- stage=1 responds=decoupler
EXPECT [toast] Can't auto-stage this ship
EXPECT [autostage] refuse: 'dec_root' would have to take the whole ship
# The other kind of refusal, said differently because that ship is not broken.
EXPECT [toast] Auto-stage: this ship has no decoupler to split
EXPECT [autostage] refuse: no decoupler in the build
# The outcome that DOES change the build, and its caveat in the log rather than on screen.
EXPECT [toast] Auto-staged 3 parts from the stack
EXPECT [autostage] note: 1 engine pair(s) carried one label and would now light apart
# Nothing technical reaches the banner, and nothing painted is wider than the screen: at a
# 28 px mono face ~16.8 px per cell, so 72 characters is the 1280 edge.
CHECK all("refuse:" not in t and "note:" not in t for t in toast)
CHECK all(len(t) < 72 for t in toast)
FORBID error:
FORBID FAILED
