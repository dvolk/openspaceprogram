# A bad --vab def is a harness typo, not a game state. It used to reach the top
# of main as an uncaught throw -- "terminate called after throwing an instance
# of 'std::runtime_error'" + SIGABRT (#16) -- while the same mistake through
# --startship already printed a clean "error: ship: cannot open ..." and exited
# 1. Now both do. EXIT 1 is what tells this apart from a crash: the refusal is
# the pass condition.
NAME vab-bad-def
ARGS --timeout 4 --vab res/ships/nope.json
EXPECT error: --vab: ship: cannot open
EXIT 1
FORBID terminate called
FORBID Segmentation
FORBID GL_
LIMIT 60
