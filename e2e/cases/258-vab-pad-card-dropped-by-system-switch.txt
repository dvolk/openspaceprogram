# A world teardown DROPS a pending question card (#304). The card used to
# survive one: this callback held the pad's TerrainBody*, the switch freed the
# body, and the answer dereferenced it -- bus error, exit 135. a1e3236 made the
# callback hold the pad by NAME; the drop makes the whole class unreachable, so
# no card can outlive the world its subject lived in.
# --switch-system is the only way in: while a card is modal every other key is
# swallowed (events.cpp:442), so a teardown can only land under a live card
# from a hook. Hence the drop is asserted through stdout, not through a click.
NAME vab-pad-card-dropped-by-system-switch
ARGS --time-accel 1 --timeout 12
ARGS --vab res/ships/tanker.json --startship racer,res/ships/racer.json,Kerbin,pad
ARGS --startship probe,res/ships/tanker.json,Kerbin,high-orbit
ARGS --vab-launch 2000 --switch-system res/systems/solar_system.json --switch-at 2500
EXPECT [vab] launch refused: 'racer' occupies 'main_space_port'
EXPECT [ask] racer is standing on Main space port. Clear the pad?  [Clear the pad | Cancel]
EXPECT [game] reset: dropped pending question: racer is standing on Main space port. Clear the pad?
EXPECT [game] switched system -> res/systems/solar_system.json
# The card never gets answered, so the by-name pad lookup never runs and the
# launch that was refused before the card went up stays refused.
FORBID [ask] answered
FORBID Cannot remove
FORBID [vab] launched
FORBID Segmentation
FORBID Assertion
FORBID GL_
FORBID error:
LIMIT 90
