# An inventory row is addressable by its place in the list.
#
# The Drop button used to be labelled plain "Drop" for every stowed part. PushID
# gave each row its own imgui id, but the test engine registers the LABEL, so a
# container holding two items registered two identical "kerbal > Staff##0/Drop"
# paths and --ui-click refused both as ambiguous -- the same defect as the seat
# rows (#326), and the same fix: a hidden id naming the row a player counts down
# the list. Unlike item->uid, the index is the same on every run, so a case can
# write it.
#
# This suit carries one item, so the case shows the row being addressed, not two
# rows colliding: the fixture with two items in one container (save_inventory's
# cargo_1) belongs to a ship the load does not make active, and its cargo part is
# occluded from the orbit camera, so opening that window would need a ship switch
# and a re-frame before it proved anything.
NAME inventory-drop-row-addressable
CLAIM Each inventory row's Drop button has a distinct addressable label.
KIND invariant
ARGS --timeout 11 --width 1920 --height 1080 --frame-cap 30
ARGS --ui-focus 7000,kerbal/kerbal_1
ARGS --sim-mouse 7050,0,CUR,CUR,RMB
ARGS --ui-click 8000,"kerbal > Staff##0/Drop##drop_0"
# Reached by the Save/Load sheet, not --load: Game Debug ticks the e2e
# fixture root, the sheet picks the "fixtures" game, the slot filter
# narrows 50 saves to this one row, and row + Load button do the rest.
# Same load_game() either way, so the assertions below are unchanged --
# and every scripted event here is shifted +5000ms because the load now
# lands at 4s, not at boot. The PERIOD presses climb the warp ladder
# where --time-accel used to: a sheet load starts paused.
ARGS --sim-press 500,0,F1
ARGS --ui-click 1000,"Game Debug/Load e2e fixture saves"
ARGS --sim-press 1500,0,F1
ARGS --ui-click 2000,"Title Menu/Save/Load"
ARGS --ui-click 2500,"fixtures"
ARGS --ui-type 3000,"Save/Load/##filter",save_inventory
ARGS --ui-click 3800,"save_inventory"
ARGS --ui-click 4000,"Save/Load/Load##saveload"
EXPECT Loaded 4 inventory item(s) with the ships
EXPECT [toast] Dropped mono_tank_r1
FORBID FAILED
FORBID ambiguous
FORBID error:
