# A pad id on an orbit bed is a config error, not a no-op. place_vehicle's
# supportMargin measures how far to lift the ship by reading the SITE's hull as
# what it rests on -- a lie when the base comes from terrain, so place_vehicle
# asserts site == nullptr || sc->on_pad (vehicle.cpp). Reject it at boot rather
# than trusting the assert. It is not compiled out here -- the Makefile never defines
# NDEBUG, so the -O2 binary aborts like any debug build (#1065 asks for that to be a
# decision rather than an assumption) -- but a crash two subsystems downstream is a
# worse report of a config error than this line is.
#
# Any real pad id makes the point; main_space_port is used now that #1063
# deleted the polar pad this case was written against. #1133 put that pad back
# as an ordinary row, and this case stays on the default port -- reaching the
# polar pad by name is pinned on its own by vab/1133-a.
NAME startship-site-on-orbit
CLAIM A pad id on an orbit bed is refused at boot.
KIND invariant
ARGS --timeout 4 --startship racer,res/ships/racer.json,Kerbin,rot-orbit,main_space_port
EXPECT error: start ships: entry 0: "site" needs an on_pad scenario, not 'rot-orbit'
EXIT 1
FORBID [vab] launched
LIMIT 60
