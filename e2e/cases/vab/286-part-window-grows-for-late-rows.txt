# A part window tracks its content, so rows that appear AFTER it opened stay
# on screen.
#
# imgui auto-fits a window for the two frames after it opens and then FREEZES the
# size (AutoFitFrames is set once, at creation), so without AlwaysAutoResize the
# window keeps the height its content had at open time. Here the capsule window
# opens with six seat rows and 443px of content in a 479px window; each Exp click
# adds a "what this kerbal carries" line under that seat, and six of them push the
# content past 530px. imgui does give a scrollbar for the overflow, so the row is
# not gone -- it is out of view behind a scroll nobody asked for, and the window
# no longer measures what it holds. imgui does not register an item that fails its
# clip test, so --ui-click reports the capsule's own Run Experiment -- the button
# at the bottom of the crew section -- as "no such item drawn". With the window
# tracking its content it moves down the screen instead, which the layout pass then
# keeps on the viewport.
NAME part-window-grows-for-late-rows
CLAIM A part window grows when rows appear after it opened.
KIND invariant
ARGS --width 1920 --height 1080 --timeout 9 --frame-cap 30
ARGS --startship power_test,res/ships/power_test.json,Kerbin,rot-orbit
ARGS --ui-focus 2000,power_test/capsule_1
ARGS --sim-mouse 2030,0,CUR,CUR,RMB
ARGS --ui-click 2500,"power_test > Capsule (4.5m)##0/Exp##exp0"
ARGS --ui-click 2700,"power_test > Capsule (4.5m)##0/Exp##exp1"
ARGS --ui-click 2900,"power_test > Capsule (4.5m)##0/Exp##exp2"
ARGS --ui-click 3100,"power_test > Capsule (4.5m)##0/Exp##exp3"
ARGS --ui-click 3300,"power_test > Capsule (4.5m)##0/Exp##exp4"
ARGS --ui-click 3500,"power_test > Capsule (4.5m)##0/Exp##exp5"
ARGS --ui-click 4200,"power_test > Capsule (4.5m)##0/Run Experiment"
EXPECT ship=power_test part=0 (capsule_r2.25h4.5)
EXPECT 'Ash' recorded 'Low orbit observation
FORBID FAILED
FORBID error:
# The six Exp clicks are the growth: every seat gains a carried-finding line, and
# Run Experiment is the row that growth pushes past the bottom edge. It runs the
# first seat, which is still Ash, so the last click is a repeat -- the claim is
# that the button is reachable at all, not what it scores.
