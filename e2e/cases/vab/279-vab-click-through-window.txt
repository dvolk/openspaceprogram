# The mirror of 278: a click INSIDE an imgui window must not place a part
# through it.
#
# This is a real bug, not a harness artefact. --sim-mouse pushes MOTION and
# BUTTON_DOWN in one poll_events batch, so on the frame the click lands the
# WantCaptureMouse the editor sampled is still the PREVIOUS frame's -- the
# cursor read as being over empty space, and the click placed a part through
# the Palette window (measured: a click at 1750,100, inside the Palette rect,
# launched 1 part). A real flick-and-click delivers the same event pair, so a
# player could do this too.
#
# vabClickAfterUI now runs after ImGui::Render, where WantCaptureMouse
# describes the frame that just drew. The Palette window is at roughly
# 1642,42..1884,60+; 1750,100 is inside it.
NAME vab-click-through-window
CLAIM A click inside a VAB window does not place a part through it.
KIND invariant
ARGS --timeout 9.5 --frame-cap 30
ARGS --ui-click 4500,"Capsule (3m)##capsule_r1.5h3"
ARGS --sim-mouse 5500,0,1750,100,LMB
ARGS --ui-click 7000,"VAB TopBar/LAUNCH"
# Reached the way a player reaches the editor: Title Menu -> New Game -> Start, then
# the 4 key.
# Game Debug turns on dev vehicles, which is what the palette and
# the dev roster need. Every scripted event here is shifted +3500ms
# because the editor opens at 2.6s, not at boot.
ARGS --ui-click 1000,"Title Menu/New Game"
ARGS --ui-click 1600,"New Game/Start"
ARGS --sim-press 2600,0,4
ARGS --sim-press 3100,0,F1
ARGS --ui-click 3600,"Game Debug/Dev vehicles in the VAB picker"
ARGS --sim-press 4100,0,F1
EXPECT [toast] Nothing to launch
# Without this the case passes vacuously: an arm click that never landed would
# leave the build empty and "Nothing to launch" would print anyway. The claim is
# that an ARMED build stays unplaced, so the arm has to be observed.
CHECK re.search(r"\[uiclick\][^\n]*Capsule \(3m\)##capsule_r1\.5h3[^\n]*pressed", out)
FORBID launched
FORBID FAILED
FORBID error:
# The part is armed by a palette click at 1000 now, so the arm the 2000 click would
# have placed is real -- and 1750,100 is itself a palette ROW (they run from y=42 in
# 18 px steps), which imgui takes as a selection. Arming is not placing: the build is
# still empty, and "Nothing to launch" is the whole claim.
