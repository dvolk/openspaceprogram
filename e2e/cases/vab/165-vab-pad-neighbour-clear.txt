# The occupancy check is per pad, not per body: a ship parked on Kerbin's KSC
# runway must not refuse a launch from the main space port. Guards the check
# from over-tightening into "any ship anywhere on this home body", which the
# COM proximity reject makes tempting.
#
# The neighbour used to be the polar pad. #1063 deleted that pad -- it was
# already 240 km from the pole once #1007 moved it off Kerbin's sea, and both
# launch doors pick a pad by name now. #1133 put it back, and the runway stays
# the better witness for exactly that reason: its deck stands 2.7 km from the
# main space port's, so "another ship
# on this body" and "another ship on this pad" are genuinely different
# questions 2.7 km apart, which is exactly where a per-body rule would bite. A
# neighbour 240 km away cannot tell those two questions apart at all.
NAME vab-pad-neighbour-clear
CLAIM Occupancy is per pad: a ship on the KSC runway does not block the main port.
KIND invariant
ARGS --startship racer,res/ships/racer.json,Kerbin,pad,ksc_runway
ARGS --ui-click 7400,"VAB TopBar/LAUNCH" --timeout 17.4
# Reached the way a player reaches the editor: the boot's start ship is already a game, then
# the 4 key.
# Game Debug turns on dev vehicles, which is what puts this def in the
# Load picker; the filter narrows the roster to one row, and row + Load
# do the rest. Same vabLoad() either way, so the assertions below are
# unchanged -- and every scripted event here is shifted +5400ms because
# the editor opens at 2.6s, not at boot.
ARGS --sim-press 1000,0,4
ARGS --sim-press 1500,0,F1
ARGS --ui-click 2000,"Game Debug/Dev vehicles in the VAB picker"
ARGS --sim-press 2500,0,F1
ARGS --ui-type 3000,"VAB TopBar/##vehfilter",tanker
ARGS --ui-click 3500,"VAB TopBar/##vabload"
ARGS --ui-click 4100,"tanker"
ARGS --ui-click 4700,"VAB TopBar/Load"
EXPECT [vab] launched 'tanker' (7 parts)
FORBID launch refused
FORBID error:
FORBID FAILED
