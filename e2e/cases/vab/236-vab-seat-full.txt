# Every seat named, and out of pad order (Cyd first): each person is taken by
# roster id, so the cast lands where the player put them rather than in the
# order the line happens to stand.
#
# Two dropdowns, filled in the order a player would fill them, then a third that
# is not filled at all. Once Cyd and Ace are seated, Seat 3 lists Cyd as
# "Cyd  (seated)" inside a BeginDisabled (drawVabPartWindow's seat rows), and the
# harness refuses a disabled widget instead of reporting a clean press -- so the
# greyed row is an assertion here, not a click that went wrong. That is the UI
# half of the one-person-two-seats rule; the launch-time refusal that guards a
# plan which went stale after it was made is pinned by seatPlanProblem now
# (tests/test_hooks.cpp).
NAME vab-seat-full
CLAIM Seats filled out of pad order land where the player put them.
KIND invariant
ARGS --kerbals e2e/fixtures/three_kerbals.json
ARGS --time-accel 1 --timeout 15.5 --frame-cap 30
ARGS --ui-click 4500,"Capsule (3m)##capsule_r1.5h3"
ARGS --sim-mouse 5500,0,960,540,LMB --sim-mouse 6000,0,960,540,RMB
ARGS --ui-click 6500,"Capsule (3m)##capsule_r1.5h3_1/Seat 1##s0"
ARGS --ui-click 7100,"##Combo_00/Cyd"
ARGS --ui-click 7700,"Capsule (3m)##capsule_r1.5h3_1/Seat 2##s1"
ARGS --ui-click 8300,"##Combo_00/Ace"
ARGS --ui-click 8900,"Capsule (3m)##capsule_r1.5h3_1/Seat 3##s2"
ARGS --ui-click 9500,"##Combo_00/Cyd  (seated)"
# The refused row leaves Seat 3's dropdown OPEN, and an open combo owns the
# mouse: a LAUNCH click then lands on the popup's scrim, not the button (the
# harness reports it as MISMATCH, nothing hovered at release). --vab-launch fired
# the launch regardless, which is exactly the difference between a hook and a
# player. The row that closes it is "Empty" -- picking a row is the only way out
# of a dropdown, and clicking the combo's own button is refused for the same
# scrim reason. Seat 3 therefore ends up EXPLICITLY empty rather than unplanned;
# that distinction is 238's claim, not this case's, and the launch is the same
# either way.
ARGS --ui-click 10000,"##Combo_00/Empty"
ARGS --ui-click 10500,"VAB TopBar/LAUNCH"
# Reached the way a player reaches the editor: Title Menu -> New Game -> Start, then
# the 4 key.
# Game Debug turns on dev vehicles, which is what the palette and
# the dev roster need. Every scripted event here is shifted +3500ms
# because the editor opens at 2.6s, not at boot.
ARGS --ui-click 1000,"Title Menu/New Game"
ARGS --ui-click 1600,"New Game/Start"
ARGS --sim-press 2600,0,4
ARGS --sim-press 3100,0,F1
ARGS --ui-click 3600,"Game Debug/Dev vehicles in the VAB picker"
ARGS --sim-press 4100,0,F1
EXPECT [vab] part window: 'capsule_r1.5h3_1' seats 3
CHECK re.search(r"Crew: 'Cyd' aboard '.*' part 0 \(1/3\)", out)
CHECK re.search(r"Crew: 'Ace' aboard '.*' part 0 \(2/3\)", out)
EXPECT [vab] launched 'Ship' (1 parts)
EXPECT path="##Combo_00/Cyd  (seated)" FAILED disabled
# The disabled refusal above is wanted, so FAILED cannot be forbidden wholesale.
# Forbid the modes that would mean the case stopped testing what it claims.
FORBID FAILED ambiguous
FORBID FAILED blocked
FORBID FAILED not found
FORBID FAILED MISMATCH
FORBID FAILED clipped
FORBID FAILED disabled at release
FORBID part window: nothing under the cursor
FORBID Crew: 'Bram'
FORBID no kerbal left
FORBID error:
