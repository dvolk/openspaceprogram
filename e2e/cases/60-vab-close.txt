# VAB "Back to game" -- the camera park/restore round trip.
#
# --ship builds a racer as the active ship and --vab opens the editor with
# tanker.json as the build tree, so entering the editor parks the FLIGHT camera
# (Game::parkCamera) and --vab-close fires vabClose at 2 s, which must hand that
# exact pose back (Game::restoreCamera).
#
# The parked/restored pair is the assertion: a camera that comes home on the
# wrong target or at the wrong distance is a silent failure -- nothing crashes,
# the view is just somewhere else -- so both lines must name the same focus and
# the same distance. focus=ship (not a body) is what proves the "ship" entry of
# focusTargets was resolved back correctly, since focusBody is an INDEX and that
# list shifts.
#
# --vab-close is the only headless path in: vabClose is otherwise a UI button
# ("Back to game"), so before this hook nothing automated covered restoreCamera.
NAME vab-close
ARGS --ship res/ships/racer.json --scenario rot-orbit
ARGS --vab res/ships/tanker.json --vab-close 2000 --timeout 10
EXPECT [vab] entered the editor (sim keeps coasting)
EXPECT [vab] back to flight (sim keeps coasting)
# the stack itself: the editor is an excursion pushed on top of flight, and
# "back to game" pops it rather than assigning a scene
EXPECT [scene] flight -> vab (push)
EXPECT [scene] vab -> flight (pop)
EXPECT [cam] parked: orbit focus=ship dist=
EXPECT [cam] restored: orbit focus=ship dist=
# both lines present (one park, one restore) ...
CHECK len(re.findall(r"\[cam\] (?:parked|restored): orbit focus=ship dist=([\d.]+) m", out)) == 2
# ... and the distance came back identical
CHECK len(set(re.findall(r"\[cam\] (?:parked|restored): orbit focus=ship dist=([\d.]+) m", out))) == 1
FORBID GL_
