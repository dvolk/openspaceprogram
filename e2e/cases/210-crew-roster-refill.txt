# A fixed pool that REFILLS. The cast lives on the home pad (StaticBuilding::crew
# / part.h): recovering 'racer' peels the seat suits off the ship and returns
# them with returnCrew before the delete (Game::recoverActive), so 'Solo' is
# standing on the pad again with no roster bookkeeping anywhere. Recover,
# re-enter the VAB, launch again: the same person takes the new seat. A roster
# that tracked assignment itself would need every delete path to remember to
# release, and the first one it forgot would shrink the pool forever.
NAME crew-roster-refill
ARGS --kerbals e2e/fixtures/tiny_kerbals.json --time-accel 1 --timeout 14 --frame-cap 30
ARGS --vab res/ships/tanker.json --startship racer,res/ships/racer.json,Kerbin,rot-orbit
ARGS --recover 2000 --recover-anywhere
ARGS --ui-click 5000,"Game Menu/VAB"
ARGS --ui-click 7500,"VAB TopBar/LAUNCH"
EXPECT Roster: 1 kerbal(s) from e2e/fixtures/tiny_kerbals.json
EXPECT Crew: 'Solo' aboard 'racer' part 0 (1/1)
EXPECT [recover] t=
EXPECT [vab] launched 'tanker' (7 parts)
EXPECT Crew: 'Solo' aboard 'tanker' part 0 (1/1)
FORBID FAILED
FORBID no kerbal left
FORBID GL_
FORBID error:
LIMIT 90
