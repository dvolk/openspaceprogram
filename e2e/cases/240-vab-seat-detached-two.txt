# Two capsules, both named, and the SECOND one is detached out of the build (a
# lone part is deleted rather than stashed). The plan for the part that left is
# dropped; the plan for the one that stayed must still fly. The ids here are
# longer than std::string's small-buffer on purpose: reading the erased entry
# after vector::erase then showed up as mojibake in the toast instead of a
# plausible part name, and a shorter id hides it.
NAME vab-seat-detached-two
ARGS --vab e2e/fixtures/two_capsules.json --kerbals e2e/fixtures/three_kerbals.json
ARGS --time-accel 1 --timeout 12 --frame-cap 30
ARGS --vab-assign 3000,1,0,Ace --vab-assign 3200,0,0,Bram
ARGS --vab-detach 1 --vab-detach-at 5000 --vab-launch 7000
EXPECT [vab] assign hook: 'capsule_r1.5h3_2' seat 0 = 'Ace'
EXPECT [vab] assign hook: 'capsule_r1.5h3_1' seat 0 = 'Bram'
EXPECT [vab] deleted capsule_r1.5h3_2 (single part, not stashed)
EXPECT [vab] dropped the seat plan for 'capsule_r1.5h3_2' 'Ace' (it left the build)
EXPECT [toast] 1 seat assignment dropped: no such seat in this build
CHECK re.search(r"Crew: 'Bram' aboard '.*' part 0 \(1/3\)", out)
EXPECT [vab] launched 'two capsules' (1 parts)
FORBID Crew: 'Ace'
FORBID Crew: 'Cyd'
FORBID No seats named
FORBID Assertion
FORBID Segmentation
FORBID GL_
FORBID error:
LIMIT 90
