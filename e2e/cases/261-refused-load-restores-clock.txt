# A refused load must not move the running game's clock (#301).
# load_game calls g.setTime(meta.time) and sets time_accel / exhaust_scale from
# the file BEFORE the ships are parsed and can throw -- it has to, because a ship
# restored into a ROTATING frame captures its rail state from the transforms that
# setTime installs. So a refusal used to leave the surviving game paused at the
# SAVE's time with its bodies parked at the SAVE's epoch.
# The running game here starts at t=500 with warp 4; the corrupt fixture's own
# clock is t=3.08, warp 1. Rails are a pure function of `time`, so Game::loadFrom
# snapshots the three fields and puts them back on the throw.
NAME refused-load-restores-clock
ARGS --system res/systems/ksp_system.json --startship racer,res/ships/racer.json,Kerbin,pad
ARGS --start-time 500 --time-accel 4
ARGS --reload e2e/fixtures/save_corrupt --reload-at 3000 --timeout 5
EXPECT [load] refused e2e/fixtures/save_corrupt
EXPECT no_such_part_in_the_catalog
EXPECT [load] clock restored:
EXPECT warp 4, exhaust 1.00x
# Back near where it was (500 + whatever warp 4 ran), not at the save's 3.08.
CHECK (lambda m: m is not None and int(m.group(1)) >= 500)(re.search(r"\[load\] clock restored: t=(\d+)\.\d, warp 4", out))
FORBID clock restored: t=3.
FORBID clock restored: t=0.
FORBID [scene] flight -> title
FORBID Segmentation
FORBID Assertion
FORBID GL_
FORBID error:
LIMIT 120
