# Ladders: climbable parts + capsule hatch ladder

Staged plan, 2026-11-21. Decisions confirmed with the user: **G** grabs/releases
(gated off `CycleTarget` while piloting a kerbal), spawn at the **top** of the
capsule ladder (the hatch), **W/S** climb ladder-relative (A/D idle in v1),
**one 2 m ladder part** + a fixture ship.

## What exists today (read these first)

- `src/eva.h` / `src/eva.cpp` — the EVA kerbal. A one-part `Vehicle` subclass with
  two regimes, `EVA_GROUND` (walk force-servo + jump) and `EVA_SPACE` (RCS +
  camera-facing attitude). Per tick: `armInput()` (active kerbal) or `disarm()`
  (every other live kerbal) arms the state; per substep: `applyEva()` runs the
  law. The regime is RE-DERIVED from pose + Bullet contact every tick
  (`updateContact`), never remembered. Pure geometry lives in `src/evamath.h`
  (glm-only, headless-testable; `tests/test_eva.cpp` pins it).
- `Game::kerbalEVA` (`src/game.cpp:1905`) — mints the walker beside the capsule:
  `offset = capDef->radius + 2.0` along a tangent picked from WORLD axes (the
  spawn side is not ship-fixed today). Grounded branch spawns at capsule-rim
  height and falls; space branch co-moves. On the `racer_legs` lander the rim is
  ~3 m up — the kerbal drops. This is what we replace.
- `Game::kerbalBoard` / `canBoard` / `kerbalInRange` (`src/game.cpp:1862+`) —
  boarding reach is `kBoardingRange = 10 m` (`src/game.h:1542`), measured
  frame-aware via `Vehicle::GetPositionRelTo(part, k->frame)`.
- Parts are FIELD-DRIVEN (`src/shipdef.h` `PartDef`, `src/part.h` `Part`):
  behavior = optional-field presence, not the type label. The catalog
  `res/data/parts.json` is GENERATED by `utils/gen_parts.py` (trimesh reads the
  meshes; `--check` is a drift gate). Mesh generators are pinned by
  `utils/check_mesh_pins.py`; mesh boxes/nodes are pinned by
  `tests/test_shipload.cpp`.
- Surface attach already works end-to-end: VAB ghost + click-place + symmetry
  (`src/vab.cpp`), ship-def edges `"attach": "surface", "angle": deg, "z": m`
  (`src/shipdef.cpp:1087+`, `attachSurface`/`surfaceMatingRot`). The landing legs
  (commit `f7cbce1a`, #1072) are the exact precedent for a surface-mounted box
  part: `srf` node on the hull-side face, generated mesh, no new attach
  machinery. `res/ships/racer_legs.json` shows the authoring format.
- Capsule meshes are frustums, top radius = bottom/4 (verified: capsule 1.0→0.25,
  r0.5h1.5 0.5→0.125, r1.5h3 1.5→0.375, r2.25h4.5 2.25→0.5625). Crewed fuselages
  are spindles (ogive nose, parallel midbody, boat-tail; `utils/gen_fuselage.py`).
- Keys (`src/keys.h`/`.cpp`): EVA = WASD + R/F up/down + Q/E yaw; SPACE = jump
  (edge via `events.cpp` → `Kerbal::pressJump`, consumed by `armInput`). G is
  `CycleTarget`, handled in `events.cpp:305` only when `camera->mode ==
  CAM_ORBIT`. One physical key may back several slots, one per mode.
- Save (`src/save.h` `SaveShip`, `src/save.cpp`): kerbal section captures pose,
  `view_yaw`, suit fuel/pockets/experiments (`saveShipFromVehicle:453+`,
  `buildKerbalFromSave:1173+`). The load commit calls `settleContact()` on every
  loaded kerbal at `save.cpp:1851` (after all ships exist) — the hook for
  restoring a grip.
- `--eva-log` row (`src/tick.cpp:1574+`) prints `[evalog] ... mode=ground|space`;
  parsed by `EVA_RE` in `e2e/run.py:479`. e2e crew cases live in
  `e2e/cases/crew/`.
- Compound hull: one Bullet body per vehicle, one child shape per part
  (`Vehicle::rebuildCompound`, `src/vehicle.cpp:1554`). A ladder part is just
  another box child — no physics-world changes needed.

## Design

### One concept: a ladder segment

A climbable line segment + outward direction, authored in the part's LOCAL
frame (+Z = stack axis convention). New optional `PartDef` field:

```json
"ladder": { "a": [x, y, z], "b": [x, y, z], "out": [x, y, z] }
```

- `a` = bottom end, `b` = top end (W climbs toward `b`), `out` = unit direction
  the kerbal hangs off (away from the hull). Presence of the field makes the
  part climbable (`Part::isLadder()` derived, like `isLeg()`).
- Parse + validate in `src/shipdef.cpp` (a != b, out non-zero → normalize;
  refuse otherwise, like node dirs). No runtime geometry inference — everything
  visible in parts.json, one mechanism for every shape.
- `utils/gen_parts.py` authors it:
  - **Capsules** (all 4): azimuth 0 (local +X), along the slope, bottom 2/3:
    `a = (R, 0, -h/2)`, `b = a + (2/3) * (r_top - R, 0, h)`,
    `out = normalize(h, 0, R - r_top)` (the slope's outward normal).
    `r_top` read off the mesh's top ring (trimesh), not a hardcoded ratio.
    Invisible: no mesh, no draw — pure data.
  - **Crewed fuselages** (all 4): vertical segment on the parallel midbody at
    azimuth 0: `a = (r_max, 0, z_mid_lo)`, `b = (r_max, 0, z_mid_hi)`,
    `out = (1, 0, 0)`; midbody z-range = stations where mesh radius >= 0.99 r_max.
  - **Ladder part**: `a = (0.05, 0, -1)`, `b = (0.05, 0, +1)`, `out = (1, 0, 0)`
    (the outer face; mount face is -X).

### The ladder part

Catalog entry `ladder`, type `ladder`, display "Ladder (2m)":

- Box: 0.1 m thick (X), 0.4 m wide (Y), 2.0 m long (Z). Mass declared 5 kg
  (declared-mass precedent: chute/leg). Blunt-body drag ~1.0, no lift.
- Nodes: `srf` at (-0.05, 0, 0) dir (-1, 0, 0) `surface: true`; `top` (0,0,1)
  dir +Z; `bottom` (0,0,-1) dir -Z — stack nodes let ladders bolt end-to-end
  exactly, surface attach puts them anywhere.
- Mesh + texture: new `utils/gen_ladder.py` writes `res/meshes/ladder.obj` +
  `res/textures/ladder.png` (flat grey with rung stripes; `gen_kerbal.py` is the
  obj+png precedent). Centred box → standard `test_shipload.cpp` centring pins
  apply; add the `srf`-node-vs-mesh-box cross-check like the leg's. Add a
  `check_mesh_pins.py` PINS entry (IN_PLACE set, like gen_leg).
- VAB: palette lists it automatically (not kerbal/fuel_link). Surface attach,
  Q/E roll, symmetry all come free. Default mount keeps the long axis along the
  parent's stack axis (vertical on a tank side).

### EVA_LADDER: the third regime

New state on `Kerbal` (`src/eva.h`), following the #578 arm/run pattern:

```
EvaMode mode;              // + EVA_LADDER
uint64_t ladderUid = 0;    // grabbed part's uid; 0 = none. SAVED.
bool grabPressed = false;  // G down-edge (events.cpp pressGrab), spent by armInput
double climbDir = 0.0;     // -1..1, armed per tick (W=+1 toward b, S=-1)
```

- **Grab/release** — `Slot::EvaGrab` bound to G. `events.cpp`: gate
  `CycleTarget` on `!(g.ship && g.ship->isEva())`; new edge handler mirrors
  `pressJump` (active kerbal, not free cam) → `k->pressGrab()`. `armInput`
  spends the edge: gripping → let go (uid 0, no kick); else find the nearest
  ladder segment within `kLadderGrabRange` of the COM → grip it (toast).
  SPACE while gripping = let go WITH an outward kick (`out * kJumpSpeed`,
  applied immediately in armInput; set the `jumping` latch like a ground jump).
- **Grip resolution** — a helper `resolveLadder(vehicles)` run wherever the
  regime is derived (armInput, the tick's disarm pass, load commit):
  - Find the part by uid among LIVE vehicles within `kBoardingRange` (frame-aware
    distance, same spelling as `kerbalInRange`). Found + has ladder →
    `mode = EVA_LADDER` (wins over any contact-derived regime). Not found →
    uid = 0, fall through to the existing ground/space derivation. Staging the
    ladder away, undocking it, or the ship parking on rails drops the grip
    naturally — no pointer lifetimes to manage (uid, not Part*).
  - **Transfer (the generosity)**: while gripping, project the COM onto the
    segment (clamped). When the projection sits at an END, look for another
    ladder segment whose distance to the COM is < `kLadderTransfer`; switch the
    grip to the nearest. End-only switching = hysteresis, no mid-ladder flicker.
    The position servo (below) slides the kerbal across gaps/offsets smoothly.
  - **Ground drop**: at the BOTTOM end, if the existing contact test says
    grounded (within `restAlt + kGroundBand`), release to `EVA_GROUND` — climb
    down onto your feet.
- **Per-substep law** (`applyEva`, ladder branch BEFORE the analytic floor
  guard — a hanging kerbal must never terrain-snap):
  - Segment world pose in the kerbal's frame: `partWorldPose` + the ship→kerbal
    frame transform (add `Vehicle::partPoseRelTo(part, relTo, pos, rot)` beside
    `GetPositionRelTo`, `vehicle.cpp:7673` — one spelling, rot included).
  - `u = normalize(B - A)`; `s = clamp(dot(pos - A, u), 0, L)`;
    `hold = A + u*s + out * kLadderHold`.
  - Along-axis velocity servo: `aAlong = (climbDir*kClimbSpeed - dot(v,u)) / h`,
    clamped to `kClimbAccel`.
  - Perpendicular position PD: `aPerp = kLadderP*(hold - pos) - kLadderD*vPerp`,
    magnitude clamped to `kLadderHoldAccel`. This is what makes imperfect
    placement compose: the kerbal is PULLED to the line, so a 0.2 m gap or a
    0.15 m lateral offset is a smooth slide, not a teleport or a refusal.
    Gravity sag ≈ g/kLadderP (~0.1 m) — acceptable, tune if it looks bad.
  - `ApplyCentralForce(mass * (u*aAlong + aPerp))`. Attitude:
    `slewTo(evaStandTarget(u, -out), h, kLadderTorque)` — body along the ladder,
    face to the hull (same helper the ground law uses).
  - The kerbal's weight does NOT load the ship (force law, not a constraint) —
    same posture as the walk law; fine for v1, note it.
- **disarm**: grip persists, `climbDir = 0` — a kerbal left on a ladder hangs
  there while the player flies another ship (the regime re-derives, #215 rule).
  The disarm pass needs the vehicle list for grip resolution; pass it (or Game&)
  through — signature change is fine, all call sites are in tick.cpp/game.cpp.
- **Hold clearance**: kerbal hull ≈ 0.3 m effective radius (0.199 + 0.1 margin),
  ladder box margin 0.1 → `kLadderHold = 0.45 m` keeps ~5 cm clearance. No
  collision-filter changes; if e2e shows contact jitter, revisit (file an issue).

### Spawn on the hatch ladder

`Game::kerbalEVA`: after minting the walker, place it at the capsule ladder's
`b` end hold point (`B + out*kLadderHold`), attitude `evaStandTarget(u, -out)`,
velocity = capsule's part velocity (co-moving; ~0 in the rotating frame when
landed), `ladderUid = capPart->uid`. ONE placement rule for landed and space —
the ladder holds the kerbal, no more rim-height drop. The world-axis tangent
machinery goes away; the spawn side is ship-fixed (+X) because the ladder is.
Keep the old beside-capsule placement as the fallback for a capsule def with no
ladder field (custom defs). `k->frame = ship->frame` already holds, so poses
are in one frame.

### Save/load

- `SaveShip` crew section: `uint64_t ladder_uid = 0;` — JSON `"ladder_uid"`,
  optional (absent = 0, pre-ladder saves load as free floaters).
- Writer: `k->ladderUid`. Loader: restore onto the kerbal; the commit pass at
  `save.cpp:1851` (all ships built) resolves the grip and sets `EVA_LADDER`
  before the first read — extend `settleContact` or add `settleLadder(vehicles)`
  called there. Unresolvable uid → clears, kerbal falls: graceful.

### Diagnostics

- `[evalog]` gains `mode=ladder` and `ladder=<uid>` (0 when none). Extend
  `EVA_RE` in `e2e/run.py` with an optional group (old rows still parse).
- Toasts on grab/let-go ("Grabbed ladder", "Let go of ladder"), `[crew]`-style
  printf on grab/release for e2e EXPECT lines.

### Tuning (one block in eva.cpp, beside the walk constants)

| constant | value | meaning |
|---|---|---|
| kClimbSpeed | 1.5 m/s | along-ladder climb rate |
| kClimbAccel | 10 m/s² | along-axis servo clamp |
| kLadderHold | 0.45 m | hang offset off the line |
| kLadderP | 100 /s² | perpendicular position spring |
| kLadderD | 20 /s | perpendicular damping (~critical) |
| kLadderHoldAccel | 30 m/s² | perpendicular clamp |
| kLadderTorque | 300 N m | attitude authority (ground's value) |
| kLadderGrabRange | 1.5 m | COM-to-segment grab reach |
| kLadderTransfer | 0.9 m | end-of-ladder transfer reach |

e2e pins BEHAVIOR (climb direction/speed band, transfer happens, hang is
stable), not these exact numbers.

### Fixture ship

`res/ships/ladder_stack.json` (name "ladderstack"): capsule + reaction_wheel +
fuel_tank + ONE ladder surface-attached on the tank at azimuth ~5° and z
slightly off-centre (deliberately imperfect). No engine → the stack rests on
the tank bottom, so the ladder's bottom end meets the ground. Covers:
capsule-ladder → tank-ladder transfer across the 0.25 m wheel gap WITH a lateral
offset, and climb-down-to-ground. `racer.json` and `racer_legs.json` stay
untouched (~500 e2e fixture lines read racer). The user tests the lander case
by hand: VAB-add ladders to racer_legs.

## Known limitations (file as issues in stage 4, ELI5 titles)

- **Warp drops the grip**: when the grabbed ship parks on rails the kerbal lets
  go and drifts (grip resolution requires a live hull). KSP keeps the grip
  through warp; a kinematic follow on rails is the fix sketch.
- **Ladders carry no load**: the kerbal's weight doesn't pull on the ship
  (force servo, not a constraint). Invisible at 90 kg vs a 10 t stack; matters
  for a lightweight station.
- **No auto-board at the hatch**: boarding stays the Board button (10 m reach).
- **A/D idle on ladders**, no shimmy around the rail, transfer only at ends.
- **One ladder size** (2 m); more lengths are a catalog edit once wanted.

## Notes for local agents

- The regime is always RE-DERIVED, never remembered (#215): any new state must
  survive `disarm()` and a paused load. The grip uid is the only durable
  ladder state; everything else comes from the pose.
- One spelling per fact: frame-aware part queries go through
  `partPoseRelTo`/`GetPositionRelTo`; distances through the same frame transform
  as `kerbalInRange`. No raw cross-frame subtraction.
- Behavior is def-field presence, not type labels — `isLadder()` reads the def,
  nothing stores a copy.
- asserts for invariants (uid resolution found a part ⇒ it has a ladder;
  segment length > 0), printf + offscreen runs when unsure.
- Keep racer.json / racer_legs.json untouched; new fixtures are new files.
- e2e budget: 1–5 cases per feature per pass; the crew directory is ~25 cases,
  run it whole only at stage 4.
