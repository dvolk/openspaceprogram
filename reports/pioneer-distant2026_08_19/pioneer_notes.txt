Pioneer — how they render distant bodies
========================================
Research notes from references/pioneer (github.com/Pioneer-Dev/pioneer),
investigated 2026-08-19. Pioneer's current renderer is OpenGL 3.2 core
(src/graphics/opengl/). Their pipeline is built on two ideas:

  1. keep everything float64 until the final per-body view matrix, and
  2. never let a distance exceed float32 precision — either remove the far
     plane entirely, or fake the distance while preserving angular size.

The codebase is at references/pioneer. All file references are relative to it.

The five techniques
-------------------

1. Infinite far plane + 32-bit FLOAT depth, reverse-Z  (the core)

   - Projection: matrix4x4f::InfinitePerspectiveMatrix(fov, aspect, zNear)
     (src/Camera.cpp:39, src/matrix4x4.h:294). Vogel's trick: z-row is
     (0,0,0,-1), so there is NO far plane, and it even accepts vertices at
     w=0 (true infinity).
   - zNear = 0.001 (1 mm), zFar = 1e8 (src/graphics/opengl/RendererGL.cpp:174).
     zFar is NOT in the projection — it only clamps billboard positions.
   - Depth: the window is created with NO depth buffer; they render to an
     offscreen FBO with a GL_DEPTH_COMPONENT32F renderbuffer
     (src/graphics/opengl/RenderTargetGL.cpp:121), reverse-Z
     glDepthFunc(GL_GEQUAL) + glClearDepth(0.0) (RendererGL.cpp:262-265).
   - Why: 32-bit float depth has ~1e-7 RELATIVE precision at any distance, so
     1e8 vs 1e12 m stay distinguishable. A 24-bit integer reverse-Z buffer
     (OSP's) collapses to depth 0 beyond ~near*2^24 = 1.68e7 m (with
     near = 1 m): everything farther is at the same depth as the background,
     so far objects are indistinguishable in depth. (OSP's far-plane sun disc
     is exactly that "background depth" — see below.)

2. float64 until the last matrix conversion

   - Camera frame = the SHIP's frame (src/ship/CameraController.cpp:36).
   - Per body, all in double:
       viewTransform = frame->GetInterpOrientRelTo(camFrame);
       viewTransform.SetTranslate(frame->GetInterpPositionRelTo(camFrame));
       viewCoords = viewTransform * body->GetInterpPosition();
     (src/Camera.cpp:195-197)
   - Frustum culling is double precision (using Frustum = FrustumT<double>,
     src/graphics/Frustum.h:44) using TestSphereInfinite, which skips the
     far plane entirely.
   - The pixel-size culling math is double too (src/Camera.cpp:217).
   - Only at draw time is there a single d->f conversion, pushed to a
     per-frame UBO:
       renderer->SetTransform(matrix4x4f(trans));   (src/TerrainBody.cpp)
       uViewProjectionMatrix * a_vertex             (data/shaders/opengl/)
     One conversion per body; nothing accumulated in float.
   - Note: OSP already does this — Body::Draw computes View*Model in double
     and converts once (src/body.h). Keep the discipline.

3. Sub-pixel bodies -> culled or point-sprite billboards  (src/Camera.cpp:205-250)

   - pixSize = windowHeight * 2.0 * rad / (camDist * fovFactor).
   - Non-terrain bodies that would render under 2 px: culled outright.
   - Terrain bodies (planets/moons) under 8 px: drawn as POINT SPRITES
     (billboards.vert: gl_PointSize = a_normal.z — size smuggled through the
     normal attribute; uv through the normal too), textured with
     textures/planet_billboard.dds, tinted star-color x planet albedo.
   - Their position is clamped to the far plane:
       scaleFactor = zFar / dist - 1e-6;
       billboardPos = viewCoords * min(scaleFactor, 1.0);
     size = max(1 px, pixSize). I.e. "far enough that it's a point,
     near enough that the depth is valid".

4. Star-shrinking: fake the distance, keep the angle  (src/TerrainBody.cpp:80-96)

   The headline trick for stars:

       // stars very far away are downscaled, because they cannot be
       // accurately drawn using actual distances
       while (dist_to_horizon > zFar * 0.5) {
           rad  *= 0.25;
           fpos *= 0.25;
       }
       ...
       if (shrink) renderer->ClearDepthBuffer();
       // shrunken objects should not interact with foreground

   - rad/len is invariant, so the star's angular size stays exact, but the
     float32 translation stays in a good-precision range.
   - The ClearDepthBuffer() after drawing erases the star's now-fake-near
     depth so it cannot wrongly occlude nearer bodies (bodies draw far->near,
     so nearer geometry overwrites it in color anyway).
   - This is exactly the class of bug that kills a naive 3D sun at 1e8 m.
     Pioneer solves it with angle-preserving rescaling; OSP currently solves
     it with a 2D far-plane disc (simpler, same idea).

5. Supporting details

   - Starfield: point sprites on a radius-1000 sphere around the camera with
     NO depth test and no depth write (src/Background.cpp:160-161), drawn
     first with a rotation-only float64 transform. Milky Way is a mesh in the
     same pass.
   - Eclipses (moon transiting the sun) are analytic in the shader:
     discCovered() in data/shaders/opengl/eclipse.glsl computes the occluded
     light fraction per pixel, mirrored in C++ (Camera::ShadowedIntensity) —
     no depth-buffer trickery for sun occultation light.
   - Body sort: far->near (sort_BodyAttrs); FLAG_DRAW_LAST bodies last.
   - Rendering uses interpolated frame transforms (GetInterpPositionRelTo)
     for sub-tick smoothness.
   - Planet geometry LOD is a user setting (4 or 5 sphere subdivisions,
     src/BaseSphere.cpp:146), not distance-driven. Terrain streams as usual.

Mapping to OSP
--------------
OSP: reverse-Z 24-bit integer depth (D24), finite perspective zFar = 1e9,
sun as a 2D far-plane disc (drawSunBg, src/main.cpp), moon at 1.2e7 m as a
real 3D sphere.

  Pioneer                         OSP today                      Verdict
  ------------------------------  -----------------------------  -------------------------
  infinite proj + 32F depth (FBO) finite zFar=1e9, 24-bit int    big architecture; only
                                            depth, default FBO   worth it for real-scale
                                                             distances (1e11+) or a
                                                             close-range 3D sun
  star-shrink + depth clear       2D far-plane sun disc          OSP's disc is the simpler
                                                             version of the same fix
  <2px cull / <8px point sprite   planets always 3D spheres      cheap, worth adding
  float64 math, one d->f at end   mostly already true            keep the discipline
  analytic eclipses               not implemented                backlog, independent

Worth noting: Pioneer's real-scale systems put stars at ~1e11+ m — a
thousand times farther than OSP's sun at ~1e8. Their whole stack (float-depth
FBO, star-shrink, billboards) is the cost of that. OSP's compressed scale is
less demanding, so the disc + finite far plane is the right ambition for now.

Ideas to steal, in priority order
---------------------------------
1. Sub-pixel handling in the planet loop (~30 lines, zero risk): compute
   pixSize per planet; skip if < 2px, else draw a tinted point sprite (<8px)
   instead of the full sphere. Kills sub-pixel precision garbage; same UX as
   Pioneer.
2. Double-precision frustum culling before drawing planets (OSP currently
   draws every planet every frame).
3. The float-depth FBO project — only if we want real-scale (uncompressed)
   star systems or a 3D sun you can land on. Multi-day change: FBO color +
   GL_DEPTH_COMPONENT32F depth + MSAA resolve + blit, following Pioneer's
   RendererGL/RenderTargetGL layout.

Known OSP depth-buffer limits (for reference)
---------------------------------------------
With near = 1.0, zFar = 1e9, reverse-Z, 24-bit depth:
  - stored depth for a body at distance d is ~ (1/d)/2 in buffer units;
  - anything beyond ~near*2^24 = 1.68e7 m stores depth 0.0 = "background";
  - so bodies farther than ~1.7e7 m are depth-indistinguishable from each
    other and from the far background — draw order (and GL_GEQUAL ties)
    decides what wins;
  - the sun disc is drawn AT background depth (NDC z=1.0 -> depth 0.0) with
    GL_GEQUAL, so it always overwrites the starfield and is always occluded
    by anything closer — correct for the current geometry;
  - the moon at 1.2e7 m still has ~1 ulp of depth, just barely.
A 32-bit float depth buffer (or FBO) is what removes this wall.
